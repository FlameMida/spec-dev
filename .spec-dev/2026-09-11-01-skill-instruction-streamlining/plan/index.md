# 技能指令精简与文档统一实施计划

> **执行方式**：使用 spec-dev executing-plans 逐任务串行执行；未获明确开始执行的指令前不运行任务。没有该 skill 的执行者从 T00 开始，按依赖选择最小编号 ready 任务；本计划与 spec 整体携带。
> **偏差处理**：路径笔误等意图明确的小偏差可就地纠正并留痕；接口、规则语义、授权或范围冲突停下核实，不猜测修改。计划正文是待执行程序，不是实施结果。
> **状态**：`plan/progress.yaml` 为唯一状态源，初始全部 pending；任务步骤不用复选框记进度。普通 v1，无集成组、无并发声明，不派写码 implementer。
> **任务读取**：执行本票时只读本票、spec 及依赖导航接口；每票完整 payload 和程序均已内嵌，不需读前票正文寻找代码。

**目标**：完成批准的 19 项整改，保持 30 项约束和排除边界。
**Spec**：[已批准设计](../spec/skill-instruction-streamlining-design.md)
**架构**：保留原技能入口，专题在所属技能内分层；统一文档权威归 requirement-analysis；DDD 全部消费同一规范。结构观察和模型行为验证分开。
**技术栈**：Markdown/YAML/JSON；Node.js 18+ 原生 node:test；Python 3.9+ 标准库；Git；本机已配置 Codex CLI。当前执行环境为 macOS/POSIX。无新增依赖。

**关联 skill**：
- 执行：`skills/executing-plans/SKILL.md`；收尾审查见其 `references/review-orchestration.md`。
- 行为任务与纯重构：`skills/test-driven-development/SKILL.md`；mock/真值见其 `references/testing-anti-patterns.md`。
- 测试策略：`skills/test-strategy/SKILL.md`；验收：`skills/acceptance-qa/SKILL.md`。
- 隔离：`skills/using-git-worktrees/SKILL.md`；实际来源和稀疏检出按 T00 本票完整程序。
- 规则拆分时保留被批准的语义；本计划沿当前执行能力操作，不提前假设候选技能已经安装生效。
- 上述路径为插件根相对；从当前实际安装根或项目根取得对应定义，不猜环境变量。实现时用户项目与插件根可能不同。

**设计原则**：不留未经需求要求的兼容垫片；最简实现；分层构建；不以未完成复杂性换可工作产品；模块化；优先成熟库；优先已有依赖；长期架构决策。判据见 `skills/writing-plans/references/design-principles.md`。保留现有导航入口是明确批准的当前接口，不是新兼容框架。

每票程序均从本票 payload 提取完整内容，写前校验原文 SHA；已为本票相同内容可复用，其他差异不覆盖。

长命令通过客户端返回的运行 ID 分段等待并保持进度沟通；没有完整退出回执时不能推进状态。
