## 步骤 3：实现两段转存

- 从原 progress 的 evidence_paths、已登记 execution 资源及 task/claim attempt 获取本特性证据闭包；保留历史失败。只接纳规范化相对路径，拒绝 symlink/逃逸。
- transfer 首先 verify 所有 manifest 和原件；目标已存在相同字节幂等，不同字节在发布前拒绝，不覆盖。
- source 与 target 不得是同一实体或相互嵌套，避免覆盖和递归转存。工具仅证明复制；清理调用方还必须证明 target 不属于将删除的 worktree/资源，不能以本票同仓库目录复制代替 T14 的真实清理后复核。
- 写到本目标归属下的独占 staging 子目录，再核对 SHA-256，逐个发布；发布不是源清理。失败返回已完成条目与缺口，供主线程保存台账，下一次核验后续接。

字节发布关键函数：
```js
export function publishEvidenceFile(source,target,expected){
 const bytes=readFileSync(source);
 const hash=createHash('sha256').update(bytes).digest('hex');
 if(hash!==expected)throw new Error('source evidence hash mismatch');
 if(existsSync(target)){
  const old=readFileSync(target);
  if(!old.equals(bytes))throw new Error('evidence target conflict');
  return {path:target,sha256:hash,reused:true};
 }
 mkdirSync(path.dirname(target),{recursive:true});
 const temporary=target+'.transfer-'+randomUUID();
 writeFileSync(temporary,bytes,{flag:'wx'});
 // linkSync 为“不覆盖已有目标”的发布；跨文件系统 staging 应在 target 同目录。
 try{linkSync(temporary,target);}finally{unlinkSync(temporary);}
 return {path:target,sha256:hash,reused:false};
}
```
调用前检查所有祖先/实体归属；如果平台不支持该原子方式，明确失败保留源，不降级成覆盖写。转存回执包含 source/target 和逐文件哈希，历史 record 字节不变。
