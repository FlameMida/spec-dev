## 步骤 3：导入并冻结原件

- 替换 initialize 内仅检查六字段形状的 evidence_ok：输入是引用，实际读取 record 和 stdout/stderr，检查归属、SHA、命令、task/phase 与当前 candidate 内容。

- 成功后把完整验证回执与原件 bytes 封存入当前 run 的 object store，broker 引用真实对象 ID。后续源文件被删除不改变已封存对象，但使用前仍校验当前 run manifest/hash。

核验桥接的完整函数：
```python
def verify_external_receipt(plugin, repo, head, ref):
    expected={'task','phase','feature','record_path'}
    if set(ref)!=expected:
        raise ValueError('evidence必须引用真实record及原件')
    result=subprocess.run(['rtk','proxy','node',str(plugin/'scripts/execution-evidence.mjs'),
        'verify','--feature',ref['feature'],'--record',ref['record_path'],
        '--candidate',head],cwd=repo,capture_output=True,text=True)
    if result.returncode:
        raise ValueError('external receipt invalid: '+result.stderr)
    checked=json.loads(result.stdout)
    if not checked.get('ok'):
        raise ValueError('external receipt unverified')
    if checked['record']['task']!=ref['task'] or checked['record']['phase']!=ref['phase']:
        raise ValueError('external receipt task/phase mismatch')
    return checked
```
原件读取路径必须使用核验输出规范路径并复核字节哈希，再 object_put，不能先校验一个文件后读取另一个。task/phase 匹配及 scope 声明写入所封存对象。

strict `snapshot()`/`verify()` 不放宽：进度改动可使原 run 拒绝恢复；同内容测试回执可供新 run 重新核验并导入，不跨 run 拼接审查成功。将新增依赖脚本/模块纳入 runtime_hashes 封存范围，避免核验器变了却旧 run 继续。
