# T15：final 全量与独立审查输入

**类型**：主线程验证票，无生产代码改动，不伪造红。

**文件**：本特性 execution/T15 与 acceptance/acceptance-report.md；progress.yaml 记录真实回执，原件不提交。任何修复回到对应实现票并使当前候选重新验证。

**接口**：全部实施出口 completed，候选干净；产出 final Receipt、审查 base/head 和覆盖对账。独立审查在 F 完成后、T16 之前执行；不得把“F completed”当已经审查。

## 步骤 1：逐 ID 入口核对

在实际实施根核对 T00—T14 全部 completed，其提交可解析；T15 本身 pending/in_progress。使用 `TID=T15 STATUS=in_progress RESULT=pending` 保存检查点，再登记 `execution/tasks/T15/` 资源并提交，确保命令前候选干净。

读取 T00.binding.source_head 作为特性审查 base，不用当前 HEAD 或切换检查点代替。记录候选 HEAD、spec/plan 路径和完整 diff。未知来源或范围不清则停下修复记录，不猜。

## 步骤 2：只在此时首次完整运行

为当前尝试生成不重复名称并运行已实现的真实回执工具：
```bash
ATTEMPT="final-$(date +%Y%m%dT%H%M%S)-$$"
FEATURE_DIR="$(rtk proxy git rev-parse --show-toplevel)/.spec-dev/2026-09-23-01-workflow-consistency"
rtk proxy node scripts/execution-evidence.mjs record --feature "$FEATURE_DIR" --task T15 --phase final --attempt "$ATTEMPT" --output acceptance/acceptance-report.md -- node --test scripts/tests/*.test.mjs
```
在同一次 shell 设置这些变量。本特性 acceptance-report.md 是本计划验证输出；执行前定向核对测试不读取它，若实际作为输入则移除 --output 并先固定该输入。检查 JSON 的被测 exit_code，不能只看 record 保存成功的 CLI exit0。输出不完整、零测试或 SKIP 不当作全量通过。

## 步骤 3：失败与补验

- 本次引入失败回所属票修复；保存旧 attempt，再为新候选执行必要验证，不覆盖旧输出。
- 范围外失败在 T00 记录的真实来源提交上比较；来源 dirty 时不得直接用它作实验，可在本计划登记的只读比较 worktree 中检出该来源 SHA，测试后按台账清理。没有可核验来源/授权条件时报告缺口。
- 来源亦失败则请用户裁决是否阻塞；保留非零回执与裁决，不把它改成全绿。来源通过则本次回归，修复后才推进。
- 影响闭包无法可靠界定则重跑全量；纯进度记录经 diff 核对后不引发无关全量重跑。

## 步骤 4：完成 F 并编排独立审查

以已有已验证 SHA 保存 T15 completed，tests 写实际 `pass` 或带有明确裁决的实际结果，不填写不存在的成功。状态提交后独立审查初始化使用新的干净 HEAD，测试 Receipt 经内容核验导入。

按本次完整 diff 声明规模；预计为 large，但以实际范围核实，large 必须 critic。选用原生 code-reviewer 编排或已具备依赖的受控 review-runner，全部维度与反驳/覆盖回执真实完成，不能把配置写好当已运行。受控 run 放在预登记的仓库外目录；运行期间不修改其快照。

高/中候选先独立反驳，适用 critic 必须有回执；确认项沿既有授权处置。修复改变候选时回补验、受影响维度复审和对账，不直接跳 T16。没有验收任务也填写 Requirement 对账；S20/S25—S27 的模型行为未执行则明确 manual-pending，不假装独立模型验收。
