把原 normalizeWrite/resolveWrite 移到 write-paths，保留默认拒绝 `.git`/`.spec-dev`；仅主线程范围解析允许精确 `.spec-dev` 路径，永不允许 `.git`。parallel-plan 从新模块导入并继续导出原接口。

readScopes 的主体（路径断言使用本票移出的真实公共路径规则）：
```js
export function readScopes(markdown,taskIds){
 const blocks=[...markdown.matchAll(/^```json spec-dev-scopes\s*\n([\s\S]*?)^```\s*$/gm)];
 if(!blocks.length)return null;
 if(blocks.length!==1)throw new Error('duplicate scope block');
 const s=parseUniqueJson(blocks[0][1]);
 if(s.version!==1||!s.tasks||Array.isArray(s.tasks))throw new Error('invalid scope version/tasks');
 for(const [id,t] of Object.entries(s.tasks)){
  if(!taskIds.includes(id)||!Array.isArray(t.writes)||!Array.isArray(t.specs)||!t.specs.length||typeof t.authorization_ref!=='string'||!t.authorization_ref.trim())throw new Error('invalid scope task '+id);
  if(Object.keys(t).some(k=>!['writes','specs','authorization_ref'].includes(k)))throw new Error('unknown scope field');
  for(const p of [...t.writes,...t.specs])normalizeWrite(p,{allowSpecDev:true});
  for(const values of [t.writes,t.specs])if(new Set(values.map(p=>p.normalize('NFC').toLowerCase())).size!==values.length)throw new Error('duplicate scope paths');
 }
 if(Object.keys(s).some(k=>!['version','tasks','final_task','acceptance_tasks'].includes(k)))throw new Error('unknown scope key');
 if(!taskIds.includes(s.final_task)||s.final_task==='T00'||!Array.isArray(s.acceptance_tasks)||s.acceptance_tasks.some(id=>!taskIds.includes(id)||id===s.final_task))throw new Error('invalid final/acceptance scope');
 return s;
}
```
scopeFingerprint 使用 SHA-256 对计划静态文本、该任务正文、scope 子项及排序的 `{spec路径,blob内容}` 序列计算；不得混入 progress、运行回执或被改业务文件。旧单文件以已识别任务标题界定正文，仅替换其复选框 `[x]/[ ]` 的状态字符；不整行丢弃。新增单文件结构不唯一时抛明确错误。

validatePlanIndex 调用 readScopes 并检查 final_task 在最大号交付票之前、验收依赖 final、final 的依赖闭包覆盖实施/组验证出口。含新块的成功回执追加 `scope_protocol_version:1`，测试核对此字段；没有新块保持原输出。parallel 有 scopes 时只收 resources 并从 scopes.tasks 取 writes；没有 scopes 才沿旧语法，不维护双定义。
