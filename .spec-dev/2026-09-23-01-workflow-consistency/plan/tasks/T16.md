**类型**：主线程最终任务。消费 T15 的实际审查/对账；不重新把首次全量放到这里。

**文件**：本特性 progress、acceptance 摘要、spec.sync_commit；资源只按 resources 处理。目标产生新差异时补验并更新相关结论。

## 步骤 1：入口与来源

逐个核对 T00—T15 completed、当前 final/审查有效；T16 本身可 pending/in_progress。使用 index 的 TID=T16、STATUS=in_progress、RESULT=pending 完整检查点命令，同次 shell 设置变量。

从 notes 唯一的 T00.binding 读取真实来源/实施路径、分支、归属和 mechanism，核对同一 Git common-dir。native 或 inherited 交回原机制取得真实合并/清理回执；下面代码只用于本计划 created+manual 的路径，不据此取得其它资源所有权。

来源原有 hooks/hooks.json 原样保留。本计划仅允许它与 T00 哈希一致、索引为空且不与实施差异相交时执行 ff-only；这项窄合并条件随计划执行授权一并确认。其它 dirty、分支变化、重叠或身份未知停止，不 reset/stash，也不提交用户文件。

## 步骤 3：实际 ff 合并及原始回执

在实际实施根运行完整代码。原生/PR 分支消费各自真实回执，仍按相同字段保存；没有发布授权不 push/create/merge，PR open 时 awaiting_merge，不能继续清理。

逐条处理 resources：成功/核实已不存在的精确条目移除并记回执；失败保留；原始证据归档、history ref 和复用资源写保留/移交。共享缓存及台账外不动。清理结果一次原子保存、一次状态提交；失败不进入锚定/完成，也不在已删除 worktree 写文件。
