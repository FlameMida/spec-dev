# T00：隔离、来源绑定与相关基线

**文件**：仅更新本特性 plan/progress.yaml；不修改 hooks/hooks.json。隔离建立在获批计划的实际 HEAD。

**接口**：消费 Git/worktree 真实回执；产出 notes 中 source_worktree/source_branch/source_head、implementation_worktree/implementation_branch、ownership、source_dirty_sha256 和实际 T00.commit。后续票不得由 common-dir 猜来源。

## 步骤 1：检测与记录来源

在 `/Users/maverick/feature-dev` 运行：
```bash
rtk proxy git status --short
rtk proxy git rev-parse --git-dir
rtk proxy git rev-parse --git-common-dir
rtk proxy git rev-parse --show-superproject-working-tree
rtk proxy git branch --show-current
rtk proxy git rev-parse HEAD
```
两个 Git dir 不同且非 submodule 则已隔离，仅跳过创建；读取原机制提供的来源与归属。普通来源预期 main，但仍消费实际结果。新增/变化的来源 dirty 范围先辨归属，不能覆盖。

## 步骤 2：创建或复用

执行时先核对原生工具能否提供创建及退出/移交的完整回执；可用则优先 `mcp__codex_app__create_worktree({name:"workflow-consistency"})`，从当前 HEAD 建立并记录返回绝对路径。当前工具清单只暴露创建，未暴露对应移除；若执行时仍不能完成原生闭环，直接使用下面可完整核验的 Git 手工路径，不先创建一个无法收尾的附着工作区。需要分支时在实际目录执行 `git switch -c codex/workflow-consistency`；已有同名分支先核对，不能 `-B` 重置。

工具不可用时完整手工路径：
```bash
rtk proxy git check-ignore -q .worktrees/workflow-consistency
rtk proxy git worktree add -b codex/workflow-consistency .worktrees/workflow-consistency HEAD
```
ignore 检查失败先核对现有规则，不能把 gitlink 加入索引。创建失败则停止本计划隔离步骤；本特性依赖真实 Git/worktree 验证，不用原地修改冒充已隔离。

## 步骤 3：保存真实绑定

把实际工具回执中的值设置为本次命令参数，不从前票 shell 继承。下面在实际实施目录运行；五个参数依次为实际来源目录、来源分支、来源 HEAD、created/inherited、native/manual。
```python
import json,hashlib,os,subprocess,sys
from pathlib import Path
def git(*a):
    return subprocess.check_output(['rtk','proxy','git',*a],text=True).strip()
p=Path('.spec-dev/2026-09-23-01-workflow-consistency/plan/progress.yaml')
s=json.loads(p.read_text())
source,branch,head,ownership,mechanism=sys.argv[1:]
assert Path(source).is_absolute() and ownership in ('created','inherited') and mechanism in ('native','manual')
binding=dict(source_worktree=source,source_branch=branch,source_head=head,
    implementation_worktree=git('rev-parse','--show-toplevel'),
    implementation_branch=git('branch','--show-current'),ownership=ownership,mechanism=mechanism)
dirty=Path(source)/'hooks/hooks.json'
binding['source_dirty_sha256']=hashlib.sha256(dirty.read_bytes()).hexdigest() if dirty.exists() else None
binding['source_status']=subprocess.check_output(['rtk','proxy','git','-C',source,'status','--porcelain=v1'],text=True)
s['notes'].append('T00.binding='+json.dumps(binding,ensure_ascii=False))
s['resources'][0]='worktree: '+binding['implementation_worktree']+' — ownership='+ownership+'; '+('remove only after verified delivery' if ownership=='created' else 'retain/hand back to original owner')
s['tasks']['T00']['status']='in_progress';s['current']='T00'
tmp=p.with_suffix('.tmp');tmp.write_text(json.dumps(s,ensure_ascii=False,indent=2)+'\n');os.replace(tmp,p)
```
用 `rtk proxy python3 -` 后附五个从本次工具回执取得的实际参数，并通过 stdin 执行代码；随后限定暂存 progress，使用纯状态提交开关提交 `chore(T00): bind actual worktree`。不把整个来源未提交工作复制进新 worktree。

## 步骤 4：相关基线

读取 package.json，确认现有 Node、Python、Git、rtk 可用；本仓库无依赖安装清单，不因 package.json 存在运行 npm install。执行 index「相关测试范围」的完整具体命令，分别保存 stdout/stderr 与退出码到本特性 `execution/T00/`（先登记目录资源）。文件不存在或命令失效只运行现存自有测试并注明，不回退全量。

预期：命令真实执行且退出 0；失败先保留输出并报告基线缺口，不开始 T01。来源 dirty 与基线失败不混为一谈。

## 步骤 5：完成检查点

令 `TID=T00 STATUS=completed RESULT=pass`，在本实施根运行 index 的完整状态保存命令。TASK_SHA 取已验证、已存在的当前 HEAD；状态提交与该 SHA 分开。没有实际基线通过不填 pass。
