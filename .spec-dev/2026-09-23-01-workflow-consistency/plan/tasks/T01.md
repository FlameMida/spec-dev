# T01：抽取可独立分发的纯记录解析

**类型**：已批准的前置纯重构，前后绿保护，不制造红。

**文件**：创建 `guardrail/lib/record-data.mjs`、`scripts/tests/helpers/group-fixture.mjs`；修改 `scripts/lib/integration-plan.mjs`、`scripts/lib/status-parse.mjs`、`scripts/tests/plan-state.test.mjs`；保护 `scripts/tests/integration-plan.test.mjs`、`scripts/tests/status-parse.test.mjs`、`scripts/tests/status-plan.test.mjs`。

**接口**：消费现有 `parseUniqueJson(text)`、`parseRecord(text)`；在 record-data.mjs 导出同名函数及 `fault(code,message)`，返回值、重复键拒绝、受限 YAML 行为和错误 code 不变。integration-plan/status-parse 原公共导出保留，避免让消费者为内部移动改协议。

```bash
rtk proxy node --test scripts/tests/integration-plan.test.mjs scripts/tests/status-parse.test.mjs scripts/tests/status-plan.test.mjs scripts/tests/plan-state.test.mjs
```
预期原公开解析、状态投影、重复键/不支持语法反例均通过；记录真实数目，不把零测试算绿。

## 步骤 2：按职责搬移

- 将 integration-plan.mjs 的 `parseUniqueJson` 连同其依赖的局部 JSON 断言移入纯模块，逐字保留算法；不要连 runtimeFacts、Git 操作或组验证一起搬。
- 将 status-parse.mjs 的 fault、uncomment、inline、parseRecordInput、parseRecord 移入同模块。`outsideFences`、parseMeta、parsePlanFiles 留原模块。
- 新模块只依赖标准语言能力；不能反向 import scripts、读取磁盘或在模块顶层执行 CLI。
- 两段原代码的 need 不可直接同名拼接：JSON 内使用保留普通 Error 的局部 jsonNeed，记录解析保留 fault/code 的 need；不得因抽取改变错误形状。

关键导出/导入对照：
```js
// scripts/lib/integration-plan.mjs：替换原 parseUniqueJson 定义
import {parseUniqueJson} from '../../guardrail/lib/record-data.mjs';
export {parseUniqueJson} from '../../guardrail/lib/record-data.mjs';
```
```js
// scripts/lib/status-parse.mjs：替换原 integration-plan 导入及记录解析段
import {parseRecord,parseUniqueJson,fault} from '../../guardrail/lib/record-data.mjs';
export {parseRecord,fault} from '../../guardrail/lib/record-data.mjs';
```
各模块余下函数仍需本地的 need/object/put 时保留其实际所需定义，不能仅因名字相同删掉消费者依赖。

为复用真实组夹具，把 plan-state.test.mjs 的 fixture/run/check/evidence/enter/waiting/archiveFixture 及实际所需 Git/hash 导入搬到 helpers/group-fixture.mjs 并导出；同时导出 git、hash、projectRoot，测试文件以 `projectRoot as root` 导入。测试本体和行为不变。新位置的仓库根使用 `path.resolve(dirname(fileURLToPath(import.meta.url)),'../../..')`。导出 `fixture()` 保持原返回 `{outer,wt,dir,state,base,save,feature}`，不把它包装成自动通过的假验证器。
