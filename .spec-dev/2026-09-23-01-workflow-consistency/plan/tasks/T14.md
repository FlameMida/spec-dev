## 步骤 1：组合场景

补三条通过实际 CLI/Git 运行的组合测试：

1. 干净临时仓库安装守卫→已提交 spec/plan→bind→实际提交→本地 bare push→全新 clone（无原工作区/日志）→range 检查；删除必要 source 对象或 task 关联后拒绝。
2. v2 合法组→真实 ignore 下 record→transfer→真实 merge 或 squash→删除原 worktree/临时分支→plan-state 终端核验；保留源 history ref，错 ref/原 cwd/哈希仍拒绝。
3. final 回执→review init→纯进度提交→原 run 拒绝恢复，新 run 可重新核验相同内容测试回执；代码/测试/契约变化时不能沿用旧覆盖，新的原件缺失不能填 pass。

所有事实由真实回执断言，不用预置 JSON state=completed 代替命令成功。完整输入从已有 fixture 组合，不在生产仓库做测试安装或 push。
