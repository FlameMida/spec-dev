### 任务 0：建立隔离工作区

**文件**：只建立已登记隔离资源并记录 progress，不改业务实现。

**接口**：
- 消费：来源分支 main、已提交计划与 index 的相关测试范围。
- 产出：经核验的隔离 worktree、原始 base_commit 与基线结果。

**步骤 1：检测已有隔离**

运行 `rtk git status --short`、`rtk proxy git rev-parse --git-dir`、`rtk proxy git rev-parse --git-common-dir`、`rtk proxy git rev-parse --show-superproject-working-tree`。git-dir/common-dir 不同且不是 submodule 时，先确认是否已有本特性隔离：同特性则复用、保存原始基线，不重做 completed；其他任务的 worktree 不冒充本特性隔离，不动其资源。

**步骤 2：建立 worktree**

优先 using-git-worktrees 的平台原生入口；本环境使用手工 worktree。运行 `rtk proxy git check-ignore -q .worktrees/`；未忽略时仅追加 `.worktrees/` 至 .gitignore 并作独立文档/配置提交，保留既有内容。来源 main 必须可核验且工作区无未知改动。

```bash
rtk proxy git rev-parse HEAD
rtk proxy git worktree add .worktrees/plan-2026-09-06-01-concurrent-execution -b plan/2026-09-06-01-concurrent-execution
```

将创建前真实 HEAD 保存为本特性最初审查 base_commit（本计划以串行执行，在 progress.notes 记持久基线与来源路径，不虚构 execution.mode）。此后所有实施命令显式以 `.worktrees/plan-2026-09-06-01-concurrent-execution` 为工作目录。不要把原工作区未提交改动拷进去。

**步骤 3：依赖与基线**

Node.js ≥18 与 git；package.json 没有依赖，不运行安装命令制造锁文件。执行 index 中全部「相关测试范围」命令并保存实际退出码。新文件尚未实现的 parallel 测试不属于 T00 基线；实现后由对应任务补跑。声明命令失效先记录并回退现存完整测试套件；真实失败按原基线阻塞纪律处理，不能标 pass。

非 git/隔离工具不可用时按 using-git-worktrees 记录未隔离及原因；本仓库正常可用时不得主动跳过隔离。任务结束原子记录真实基线与提交，不提前创建 implementer；这是交付并发 skill 的开发计划，仍由现有串行流程实施。
