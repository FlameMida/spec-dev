## 2. 真实 Git 夹具与受控执行者

夹具位于已预登记的本实施 worktree 内 `.parallel-qa/`（临时目录，勿提交）。先确认路径不存在；若已存在先按 progress 台账核验归属，不覆盖。下面脚本只创建真实 Git 基础设施和可控工作进程，不实现调度器；由验收主线程按已交付 skill 执行检查、认领、合并与恢复动作，不能把脚本自身实现的状态机当作 skill 已被验证。

将下列全文保存为 `.parallel-qa-setup.mjs`，在本实施 worktree 根运行 `rtk proxy node .parallel-qa-setup.mjs`。脚本与目录均已预登记。输出 QA_ROOT 供后续所有命令显式指定；本仓库正常 hooks 不被改动，夹具仓库本身无发布动作。

```js
import { mkdirSync, existsSync, writeFileSync } from "node:fs";
import { execFileSync } from "node:child_process";
import path from "node:path";
const root=path.resolve(".parallel-qa");
if(existsSync(root)) throw new Error("fixture already exists; inspect ownership first");
mkdirSync(root); const repo=path.join(root,"repo"); mkdirSync(repo);
const git=(cwd,...args)=>execFileSync("git",["-C",cwd,...args],{encoding:"utf8"}).trim();
git(repo,"init","-b","main");git(repo,"config","user.name","Protocol fixture");git(repo,"config","user.email","fixture@example.invalid");
writeFileSync(path.join(repo,"base.txt"),"base\n");git(repo,"add","base.txt");git(repo,"commit","-m","fixture base");
const base=git(repo,"rev-parse","HEAD");
git(repo,"worktree","add",path.join(root,"integration"),"-b","feature",base);
for(const id of ["a","b"]) git(repo,"worktree","add",path.join(root,id),"-b",`ticket/${id}`,base);
writeFileSync(path.join(root,"fixture.json"),JSON.stringify({root,repo,base,integration:path.join(root,"integration"),tickets:["a","b"]},null,2));
const worker=`import {writeFileSync,existsSync} from 'node:fs';
import {execFileSync} from 'node:child_process';
import path from 'node:path';
const [root,id]=process.argv.slice(2);const cwd=path.join(root,id);
const git=(...args)=>execFileSync('git',['-C',cwd,...args],{encoding:'utf8'}).trim();
writeFileSync(path.join(root,id+'.started'),String(Date.now()));
while(!existsSync(path.join(root,'release'))) await new Promise(r=>setTimeout(r,25));
writeFileSync(path.join(cwd,id+'.txt'),id+'\\n');git('add',id+'.txt');git('commit','-m','fixture '+id);
writeFileSync(path.join(root,id+'.finished'),JSON.stringify({at:Date.now(),commit:git('rev-parse','HEAD')}));
`;
writeFileSync(path.join(root,"worker.mjs"),worker);
console.log(JSON.stringify({QA_ROOT:root,base},null,2));
```

首次 setup 仅用于准备 Git 事实。S08/S23 的正式演练必须先按 skill 保存授权、完成 T00、锁、模型声明、activation（切换时）和 claim，再从当时 validated_commit **新建**对应票工作区；删除/重建只针对本夹具自身尚未运行且零改动的预备 a/b，先核对。不得把上述预备 worktree 的旧 base 当新 claim 基线。模型声明必须说明后面的 Node 进程是受控执行者、没有模型/思考强度，不冒充真实 implementer。

在同一 tool orchestration 中异步启动两个真实进程 `node <QA_ROOT>/worker.mjs <QA_ROOT> a` 和 `... b`（不 await 第一进程完成后再启动第二个）。观察两个 `.started` 都存在，再写空的 `<QA_ROOT>/release`；等待两进程退出。断言 `max(a.started,b.started) < min(a.finished.at,b.finished.at)`，保存时间戳、两个分支 tip 和 `git log --all --graph --oneline`。这证明受控执行者确有时间重叠，不证明真实模型多轮遵循。

主线程按 skill 接收并逐票 merge，先跑 `git -C <integration> merge --no-edit <ticket tip>`，核对文件后保存真实集成验证日志和 completed 状态；后继只在持久化 completed 后允许 ready。不把上述 worker 的无 TDD 提交当 implementation-result ready；S14 的真实红绿证据由下一节另行演练，worker 只用于验证 Git 并发事实。
