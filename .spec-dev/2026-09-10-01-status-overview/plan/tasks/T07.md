### 任务 7：本地交付、资源处置与锚定

**文件**：
- 修改：本spec、plan/progress.yaml、roadmap的AB-34胶囊。
- 创建：本特性execution/serial/T07/{archive.json,merge.json,cleanup.json}及acceptance/resources/qa-scope.tgz（实际有scope时）。
- 资源：只消费T00绑定和progress中的本计划所有权；不push/发布，不清全局缓存/客户端历史。

**接口**：
- 消费：T06全部必需通过、同候选全量测试/审查与真实模型判读、T00实际source/worktree/branch/base/owned。
- 产出：实际合并提交、归档/清理回执、sync_commit与T07完成；roadmap仅记录AB-34交付，#8其余留观项不自动结项。

**步骤 1：交付前核对**

使用executing-plans收尾审查与acceptance-qa的真实结论。核对本spec S01—S26全部必需通过、T06 full exit0且源码哈希与当前候选一致；只有新增源码/测试变化或未解决疑虑才重跑安全网。检查测试退役双条件：本项仅新增能力且supersedes为空，若不存在已REMOVED/Superseded的现行Scenario对应测试，则记录无孤儿测试、无取代回写；不因历史命名不一致删测试。

若存在有条件豁免或未验证必需项，保持blocked并保存证据，不进入后续合并。S26 nightly多trial是已声明非阻塞，可not_run，但3例PR模型动作不可豁免。

**步骤 3：合并回实际来源**

不用git-common-dir的父目录猜主工作区。以下块先dry-run merge-tree；发现冲突/脏工作区停下保留原件。若T00复用外部隔离（owned=false），本计划不自行合并/删除该隔离，需原机制完成交付并提供实际合并事实后按本步骤的同等核验续接；未取得时T07保持blocked，不能宣称来源分支已交付。

```python
import json,subprocess
from pathlib import Path
ROOT=Path.cwd().resolve();F=Path('.spec-dev/2026-09-10-01-status-overview');s=json.loads((F/'plan/progress.yaml').read_text())

def git(*args,cwd=ROOT):return subprocess.check_output(['rtk','proxy','git',*args],cwd=cwd,text=True).strip()

assert not git('status','--porcelain=v1')

subprocess.run(['rtk','proxy','git','merge-base','--is-ancestor',b['base'],source_before],cwd=source,check=True)
```

随后所有写入/提交都从输出source目录进行，不能在即将删除的worktree里更新progress。

**步骤 4：清理已归档自有资源**

从实际source根执行下面块。它先保存merge回执，再对归档哈希和scope归属核对；逐条更新状态并提交，失败保留未清部分。只有本计划owned worktree允许git worktree remove；分支单独删除。禁止--force、reset、stash或全局clean。

