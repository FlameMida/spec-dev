# ADR-0009: 按已提交任务范围核验计划实施

**Status**: Accepted (2026-09-23)

spec 在实施前激活并提交，守卫却只看代码与 spec 是否同批修改，会拦截正常计划实施。采用原计划载体中的精确任务写集合、已提交版本与授权来源关联，本地核对实际工作区/claim，提交历史保留可移植任务关联；运行状态仍在原 progress 或旧单文件复选框，操作回执只定位权威。范围匹配只免对应已处理 spec 的同批修改要求，不能证明用户批准或实现语义；测试、审查、多契约处理和原例外授权继续有效。

未完成旧计划在恢复时补齐当前/未执行任务，保留原格式及历史；不建立授权服务、第二份状态或编译快照。守卫保持独立分发，不复制完整插件校验器；ADR-0005/0006/0007 的载体、分发和唯一写者决定继续有效。

被否方案：沿用整次宽跳过无法持续限定任务范围；仅凭 active、in_progress 或普通 Spec trailer 放行无法核验版本和写集。用户已于完整设计中批准本决定；这不授予实施或发布权限。

设计：[工作流一致性](../2026-09-23-01-workflow-consistency/spec/workflow-consistency-design.md)。
