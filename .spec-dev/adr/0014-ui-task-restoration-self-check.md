# ADR-0014: 界面任务内的还原自查属于实现，由获批计划授权

**Status**: Accepted (2026-11-10)

## 背景

ADR-0013 把回归与验收改为收尾先问后做，原型契约随之写下"executing-plans 不在任务内自行做页面对照"。结果是实现期间没有任何对照定稿的环节：页面与定稿的偏差要等全部任务完成、且用户在询问门选了对照才会被发现。用户于 2026-11-10 要求计划实施时高保真还原定稿。

## 决定

spec 采纳了界面定稿时，writing-plans 在界面任务里写一步"还原自查"，executing-plans 在该任务的目标测试转绿后，以相同的角色、数据、视口和状态并排对照定稿并修正差异，结果记入执行记录。

这一步是实现的一部分：不产生验收结论，不替代询问门里由用户判断的对照。授权来自用户批准的计划，用户可以在批准计划时去掉它。没有浏览器能力或应用起不来时记"未自查"并继续。

## 与 ADR-0013 的关系

不推翻 ADR-0013 的任何结论。全部任务完成后的 HARD-GATE、询问门和"拿不到回复按未同意处理"保持原样；回归、E2E、性能验收和 acceptance-qa 仍然只在用户选择后执行。本决定规定的是任务内、由获批计划写明的步骤，落在 ADR-0013 第 3 条"只做任务写明的事"之内。

## 被否方案

- 只在询问门对照：偏差发现得晚，用户不选就完全没有对照。
- 每个界面任务自动对照、不写进计划：没有可追溯的授权，与"未经用户选择不运行浏览器验收"相悖。

## 代价

- 每个界面任务多一次启动应用和浏览器操作。
- 自查由实现者自己做，是弱证据，不能代替由用户判断的验收。
