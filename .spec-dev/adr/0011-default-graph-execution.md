# ADR-0011: 统一执行入口默认按依赖图并发编排

**Status**: Accepted (2026-10-10)
**Supersedes**: ADR-0007, ADR-0010

用户在对照上游 implement-spec 后明确要求本项目同样默认并行。本决定完整承接 ADR-0007 与 ADR-0010 的有效结论，替换其独立执行 skill、默认串行与额外并发选择门；既有正文作为历史保留。

executing-plans 统一载入、调度、恢复和交付。用户授权执行计划后，默认按依赖图派发已声明且具备测试与隔离条件的票；不另问并发许可，也不要求至少两条独立链。单票 ready、依赖链或排他资源自然使同时运行数量降为一，多个无冲突 ready 票可并发。明确串行要求优先；缺声明、无合格票或平台不能隔离时由主线程顺序推进，状态不明或声明损坏先解决具体阻塞。执行授权仍是前提，仅批准设计/计划或提供路径不启动实施。独立并发 skill 及旧 reference 目录移除，全部现行引用和评估归入 executing-plans；历史计划和交付记录保留。

保持 ADR-0005 的三件套、四列导航、progress 唯一运行状态及拒绝编译快照，保持 ADR-0006 的插件根规则；按 ADR-0009 由 scopes 唯一定义精确写入，parallel 声明派发资格和排他资源。主线程唯一写 progress 并集成，派发前持锁、保存 claim、建立独立 worktree 与绑定；implementer 每票 TDD 和契约自检，不修改共享进度、不承担 merger。实际集成验证并持久化 completed 后才解锁后继；每次完成即重算 frontier，不等待整批结束。模型声明、越界拒收、中断核验与不重复认领继续有效。

恢复先续接当前票、活动组和存活 claim，不重做 completed 或覆盖原始审查基线。没有明确串行要求的历史串行计划，可在干净且可核验的完成边界按默认策略激活；激活记录引用执行授权与默认规则，不伪造用户并发原话。明确串行偏好沿已有 notes 保存，恢复和默认策略都不能撤销它。旧单文件保持原格式；不为默认并发猜测写集合或批量迁移历史。

完整承接集成组协议：每批保留独立任务与实现提交，成员操作和局部检查完成后为 awaiting_verification，仅同组显式依赖可消费，组外等唯一验证出口。主线程持同一特性锁，收拢在途工作后独占集成区；全部组验证通过才原子完成成员、验证票与组并推进基线。组员和组验证不进入普通 implementer 接收；不新增组状态文件、执行器版本域或进度分片，含组继续 v2。组身份不豁免行为红、普通票接收、全局审查、验收或最终验证。

完整承接证据与交付规则：代码进入 Git，执行原件按独立 attempt 在本地完整保存，进度/引用提交，原件无需 force-add。清理 worktree 前转存至已确认存活位置并核验，失败/冲突保留现场，原 cwd 和历史不改写。票级合入保留 ancestry；最终 squash 保留来源历史锚，并在唯一进度载体核验已验证来源到真实目标的内容与交付关系。PR ready 不等于交付，独立 final 先于审查和验收，修复后按影响补验。

继续采用 ADR-0001/0002/0005/0006/0009 的其他现行约束。本决定不授予计划外实施、推送或发布权限；不采用多个代理写共享目录、自动猜测冲突处置、以实现提交代替集成完成，或用 completed 表示组内中间态。
