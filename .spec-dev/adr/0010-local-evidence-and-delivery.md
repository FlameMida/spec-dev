# ADR-0010: 集成组保留待验协议，证据本地保存并核验最终交付

**Status**: Accepted (2026-09-23)
**Supersedes**: ADR-0008

完整承接集成组决定：每批有独立任务和实现提交，成员操作及局部检查保存后进入 awaiting_verification；只有同组显式依赖可消费，组外等待唯一组验证出口。主线程持既有特性锁，收拢在途执行者后独占集成工作区；全部组验证通过才一次原子完成成员、验证票与组并推进基线，中断后按真实 Git、绑定和证据恢复。

代码进入 Git，原始执行证据在本地按独立 attempt 完整落盘，进度/引用按所属任务保存并提交；取消“证据与进度分开提交”中的证据提交义务，以符合现行 ignore 和本地留存政策。删除 worktree 前向已确认存活位置转存并核对原件，冲突/失败保留现场；原 cwd、失败和成员历史不改写。最终交付在唯一进度载体连接已验证来源与真实目标，最终 squash 保留本地来源历史锚并核验内容/交付关系，票级 ancestry 仍严格执行。

继续沿用三件套、四列导航、progress 唯一状态源和含组 v2，不增执行器版本域、编译快照或独立组状态文件；默认串行，并发须用户明确选择。组员与组验证由主线程执行，不进入普通 implementer 接收；普通票 TDD/接收、实际集成后完成、原始审查基线、收尾审查、验收和真实交付不因组身份省略。final 时点按获批工作流一致性设计前移，不取消全量安全网。ADR-0001/0002/0005/0006/0007 继续有效；本决定不授予实施、推送或发布权限。

被否方案：force-add 原始证据违反本地留存；改写历史 cwd 或放宽所有 ancestry 会失去原事实校验；删除来源历史后仅保留 SHA 不能满足后续核验。原 ADR-0008 否决的“用 completed 表示中间态、多个 agent 写共享目录、另建组状态文件、把多票折成大票”仍不采用。

设计：[工作流一致性](../2026-09-23-01-workflow-consistency/spec/workflow-consistency-design.md)。
