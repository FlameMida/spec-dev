# ADR-0013: 简化工作流——一页 spec、单文件计划、询问门、守卫交付时激活、skill 自包含

**Status**: Accepted (2026-11-10)
**Supersedes**: ADR-0001, ADR-0005, ADR-0006, ADR-0009, ADR-0011, ADR-0012

## 背景

执行一份计划要经过隔离与基线、每任务绑定与两次提交、独立 final、多路审查、验收、对账和交付核验，写计划到执行要读的规则约 158KB；其中真正防跑偏的只有单文件计划、任务接口、每任务 TDD 与自检、三档偏差处理这几条，其余多是在证明流程被执行过。仓库里 19 份 active spec 在后续大改中无人同步。用户的实际分发方式只同步 `skills/` 目录，skill 里约 20 处对 `scripts/`、`agents/`、`guardrail/` 的引用在这种装法下不可用。用户于 2026-11-10 逐项裁决了简化方向。

## 决定

1. **spec 是一页契约**：目标与成功标准、非目标、关键决策、Requirement 与 Scenario。默认不带 frontmatter，是本次变更的契约，交付后冻结成历史；长期有效的行为由以 Scenario 命名的测试守护。
2. **计划是单个文件**：头部、任务导航、各任务、执行记录。复选框是唯一的进度状态。计划里没有隔离、final、验收、交付任务，没有写集合块和资源台账。
3. **执行期不做基线**：建好工作区、装好依赖即开工。每个任务重读计划头部，只做任务写明的事，目标测试先红后绿，已提交的断言不为转绿而改，一次提交并自检。
4. **收尾先问后做**：全部任务完成后做一次轻量独立审查（默认一路，大变更两路），然后在询问门一次问清回归、验收和交付。未经用户选择不运行全量或回归套件、E2E、浏览器或性能验收；拿不到回复按未同意处理。
5. **守卫在交付时激活**：需要漂移守卫的 spec 才加 frontmatter。实施期间它在特性分支上保持 draft，交付提交翻 active。任务绑定整体移除；历史上带 `Spec-Task` 的提交告警放行。
6. **skill 自包含**：skill 只依赖 `skills/` 目录里的文件。子代理定义改为 skill 内的 brief，由通用子代理按路径读取；正文按能力描述，宿主专有的工具名只出现在 host-compat；没有某项能力时按统一规则降级并注明。
7. **需求设计四步、一次批准**：理解与探索、逐题澄清、设计提案、落盘 spec。档位只调节探索深度。

## 仍然有效的结论（完整重述）

- **自 ADR-0001**：取代的生效时点分两轨。ADR 的取代在裁决落盘时立即回写。spec 的取代对主分支随交付生效，实施期间主分支上的旧 spec 保持原状。
- **自 ADR-0005**（含它承接的 ADR-0004）：计划只有一种写出形态，读取对历史形态宽容，旧计划按原样读取、不迁移。进度只有一个事实源，不设第二份状态文件。不引入执行器版本域、编译快照或 skill 注册。
- **自 ADR-0006**：插件命令引用插件内文件一律写成 `"${CLAUDE_PLUGIN_ROOT}/<相对插件根路径>"`，平台没有替换时按单点定义的三级解析序列代入。不随守卫安装器向目标仓库分发校验器副本。
- **自 ADR-0009**：守卫独立分发，不复制完整的插件校验器。普通的 `Spec:` trailer 只作追溯，不能放行未同步的提交。契约不变的例外仍需授权并留下 `Spec-Guard: off <原因>`。范围或状态上的放行不证明实现语义正确，测试和审查继续有效。
- **自 ADR-0011**（含它承接的 ADR-0007、ADR-0010）：executing-plans 是载入、执行、恢复和交付的唯一入口。执行授权是前提，只批准设计或只提供路径不启动实施。主线程实施并且是计划文件的唯一写者。恢复时不重做已完成的任务。PR 就绪不等于交付。
- **自 ADR-0012**：插件不要求也不注册外部 MCP 服务。浏览器操作使用 ego-lite 与官方 ego-browser skill，缺失时如实标记未验证的范围，既有的确定性测试可以独立继续。不分发 sequential-thinking。AnySearch 及其上游同步行为不变。

## 被推翻的结论

- **ADR-0001**：实施窗口期的 Superseded-pending 标注和 `sync_commit` 锚定取消。旧 spec 的状态改动放在特性分支的第一次提交，随合并生效。
- **ADR-0005**：分文件三件套、`progress.yaml` 和任务去复选框不再是写出形态。v9.2.0 已恢复单文件加复选框，本决定予以确认。
- **ADR-0006**：skill 正文不再“载入即声明”插件根。skill 只引用自己目录下的文件，插件根只供插件命令使用。
- **ADR-0009**：任务写集合、本地绑定和 `Spec-Task` 提交关联整体移除。
- **ADR-0011**：默认并发、集成组、本地保存的执行证据、交付映射核验，以及“独立 final 先于审查和验收”取消。v9.2.0 已恢复串行，本决定进一步把 final 与验收改为先问后做。
- **ADR-0012**：受控审查已删除，它按需生成本地 stdio 工具配置的条款随之失效。

## 被否方案

- 保留任务绑定只做瘦身：每任务仍要三条绑定命令和两次提交，是流程开销的主要来源。
- 回归与验收默认执行、允许用户关闭：与“未经询问不得自行执行”的要求相反。
- 保留 `agents/` 目录：只同步 skills 的装法拿不到它，Codex 也不读取。
- 逐份改写 19 份旧 spec：它们描述的是已被替换的机制，改写成本高且仍会过期。

## 代价

- 没有基线，开工前不知道哪些测试本来就红；改为遇到无关失败时在分支起点复跑单个用例。
- 没有范围绑定，写到任务声明之外的文件不再被机械拦截，靠每任务自检和收尾审查发现。
- 守卫交付时才激活，实施期间特性分支上的该特性不受守卫保护；主分支不受影响。
- 删除 `agents/` 后，Claude Code 上的审查子代理失去工具级的只读限制，改为 brief 要求只读、审查返回后核对工作区无改动。
