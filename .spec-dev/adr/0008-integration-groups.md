# ADR-0008: 集成组——独立任务待验，主线程独占并统一验证

**Status**: Superseded by [ADR-0010](0010-local-evidence-and-delivery.md) (2026-09-23)

## 背景

宽面迁移即使采用 expand–contract，也可能无法逐批独立通过全部相关验证。把全部批次并成一张大票会扩大上下文与恢复单位；让中间票直接 completed 又会使后继消费未验证代码。用户于 2026-09-07 明确选择多票集成组，并批准完整的状态、依赖和恢复设计。

## 决定

保留每批独立 TNN 文件与实现提交，用显式集成组和唯一组验证任务承载共同完成条件。组员操作与可运行检查保存后进入 `awaiting_verification`；只有同组显式依赖可以消费该状态，组外通过验证票出口等待。主线程持有既有特性锁、收拢在途执行者后独占现有隔离集成工作区；整体通过后一次原子更新组员、验证票、组和已验证基线，代码/证据与进度分开提交，崩溃后按实际 Git 与证据恢复。

沿用 ADR-0005 的三件套、四列导航和 progress 唯一运行状态；含组采用新的进度数据格式，不增加 executor 版本域、编译快照或 skill 注册。沿用 ADR-0007 的默认串行、并发显式授权、主线程唯一写状态、普通 implementer 每票五步及集成后完成、原始审查基线和完整收尾；组员是主线程专属票，不进入普通 implementer/implementation-result 接收路径。ADR-0006 的插件根及 ADR-0001/0002 的取代生命周期保持。本决定补充上述 ADR，不推翻其既有决定，也不授予实施、推送或发布权限。

## 理由与被否方案

组内待验状态把“操作已做”与“验证通过”分开，可保存细粒度任务和中断记录，又不会推进未验证基线。代价是新增依赖出口、数据校验和恢复规则，用户已选择承担该复杂度。

被否方案：单张原子大票（用户选择多卡追踪）；把中间票标 completed（制造假完成）；多个 agent 写同一集成目录（写者/状态竞争）；独立组状态文件（破坏唯一状态源）；取消第二级降级（丢失路线图已批准范围）。
