# ADR-0005: plan 单一形态(写收敛、读宽容)

**Status**: Accepted (2026-08-27)
**Supersedes**: ADR-0004

writing-plans 产物收敛为**唯一分文件形态**(index.md + tasks/TNN.md + progress.yaml),删除阈值门控与单文件生成能力;executing-plans 保留格式嗅探读分支,存量单文件计划按原样读取执行(写收敛、读宽容)。任务文件步骤用「**步骤 N:**」标题式、不再使用复选框——progress.yaml 是唯一状态源。

理由:v8.0.0 交付的实证——双形态要求每条新纪律在两侧各写一遍,"资源预登记按形态分流"在 writing-plans 侧三处全部漏落地(审查发现 R4),分叉本身制造缝隙;106KB 单文件计划跨会话执行时每任务需回捞计划段落、恢复靠 git log 与未提交文件推断,执行体验上分文件严格占优。**对 v5.5.0 前车之鉴的回应**(ADR-0004 记载其失败于"双事实源 + 文档运行时双轨同步"的维护成本):本决策继承 0004 已验证的"单一事实源"回应(任务正文只在 tasks/、状态只在 progress、复选框双轨废除——本 ADR 更进一步从"分文件形态弃用复选框"扩为"任务模板全局去复选框"),当年强制形态的失败根因不在"每计划多几个文件",在双轨同步——该根因已消除。

仍有效的结论(自 ADR-0004 完整重述):三件套结构(index 导航表四列契约/tasks 每任务一文件/progress.yaml 唯一运行时状态);弃用复选框双轨;拒绝 writing-plan-plus 的 executor 版本域/编译快照/skill 注册(违反最简实现)。被推翻的结论:阈值门控(>8 任务/25KB)与"低于阈值维持单文件"的双形态并存——写路径不再产出单文件。

被否方案:保留双形态仅补齐分流条款(治标,缝隙类别仍在);两步走先删阈值后合并文档(制造新的中间态,恰为本次要消除的过渡形态);全量旧计划迁移脚本(读取历史产物是读历史数据,非兼容垫片,见 design-principles 第 1 条注解——迁移属可选项非前置条件)。
