**步骤 2：交付对账与部分取代回写**

只有 T05 PR 必需检查通过才做回写，nightly unverified 单列。13 条 Requirement 逐条核对，未交付条目不能写 DELIVERED。在 worktree 对旧 spec 作唯一范围的回写：

```python
from pathlib import Path

text = p.read_text()
```

**步骤 3：合并来源**

先保存全部已接受证据并提交，检查来源工作区实际 branch=main、无未知 dirty；当前特性分支已经过审查/验收，不能合并未验证改动。正常本地来源未推进时：

```bash
rtk proxy git -C /Users/maverick/feature-dev status --short
rtk proxy git -C /Users/maverick/feature-dev merge --ff-only plan/2026-09-06-02-tdd-seam
```

来源发生分叉则先核对差异及冲突，按已有授权正常集成并验证；不能强制移动来源。来源 dirty/冲突需保留现场裁决。实际合并树与已验收树一致才报告接受，不能以分支名字证明交付。

**步骤 4：资源清理**

先确认归档证据已在 main，且资源无运行者、无未提交结果。仅遍历 progress.resources 的本特性资源：

```bash
rtk proxy git -C /Users/maverick/feature-dev worktree remove /Users/maverick/feature-dev/.worktrees/plan-2026-09-06-02-tdd-seam
```

失败保留台账，不 force。模型夹具在 worktree 内已归档，无需删外部资源；共享缓存和其他 worktree 不动。复用的非本计划隔离由原生命周期处理，明确记录不清理原因。
