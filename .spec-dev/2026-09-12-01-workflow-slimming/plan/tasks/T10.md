**步骤 3：写最小实现**

delivery-templates.md 步骤 5 段中「逐条核对台账归属与资源实体，执行本计划拥有资源的清理命令；worktree 与分支分开核对结果，不把部分成功写成全部完成。每条成功后原子移除对应条目并追加真实 notes；失败则保留未清部分、保存 blocked 并停止后继锚定/完成；已不存在则核实后移除并记"已不存在"。」→
> 逐条核对台账归属与资源实体，执行本计划拥有资源的清理命令；worktree 与分支分开核对结果，不把部分成功写成全部完成。全部条目执行完毕后**一次保存**：成功条目移除、失败条目保留并整体记 blocked、已不存在条目核实后移除并记"已不存在"，notes 逐条追加真实结果；随后**一次提交**（`chore(TNN): cleanup ledger`）。中途失败同样一次保存一次提交后停止后继锚定/完成。

同段「每次状态变化给出实际提交步骤，不能在被删的 worktree 中继续写文件。」→「不能在被删的 worktree 中继续写文件。」

integration-groups.md `register_evidence`：
- 「`require(state == saved, "stale resource state; reload the committed checkpoint")`」→「`require(state["tasks"] == saved["tasks"], "stale task state; reload the committed checkpoint")`」（允许同票内多次登记在内存累积）。
- 删除「`checkpoint(receipt, state, "chore: register " + directory)`」一行，原位改为注释「`# 登记随本票的下一次 checkpoint 一起提交，不单独提交`」。
- `:346`「它先提交资源台账并预检，随后 `record_check` 才允许在该目录下创建唯一 attempt」→「它把台账写入内存 state 并预检，随本票的下一次 checkpoint 一起提交；登记后 `record_check` 即可在该目录下创建唯一 attempt」。

executing-plans SKILL.md `:94`「不延迟到收尾补记；」→「不延迟到收尾补记，登记随本任务的提交一起提交、不为单个资源单独提交；」。
