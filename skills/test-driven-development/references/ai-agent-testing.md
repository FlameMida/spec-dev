# AI Agent 测试处方

> **阅读时机**：被测系统含 LLM 或 Agent 行为时。

## 测试骨架（模型边界是唯一不可逆的决策）

用一根窄接口隔离模型，模型是它之外唯一的依赖；边界以下全部确定性。

任务内自动运行的层：

- L0 静态检查加工具的 JSON Schema 校验（schema 漂移是工具类的头号故障）。
- L1 harness 单测：fake model 按序弹出响应，测循环控制、路由、重试、预算、护栏。
- L1.5 prompt 快照：快照装配后的最终 prompt（确定性的），不是模型输出。
- L2 工具契约：工具就是普通函数，按普通函数单测。
- L3 回放：录制后回放（脱敏），周期性重录。

需要真实模型、要先问用户的层：

- L4 廉价模型冒烟：小模型加严格的 schema 断言，只在 agent 相关变更时考虑。
- L5 完整 eval：真实模型、多次 trial、pass^k、按维度隔离 judge。

断言纪律：`temperature=0` 不等于确定性。断言面向结构与 schema，不面向精确文本；评结果不评路径，精确的工具调用序列断言很脆弱。

## eval 细则

- **grader 分级**：确定性优先（end-state 断言、工具调用形状、直接跑测试套件）；LLM judge 只兜主观余量，每个维度独立 judge，给 Unknown 出口，并与人工标注校准。
- **pass@k 与 pass^k**：一次成功即可的生成类用 pass@k；要求一致性的用 pass^k。单次 75% 时 pass^3 约 42%，单跑一次 eval 全是噪声，20 到 50 个任务起步。
- **golden 数据集是代码**：文件化进仓库走评审；回归套件（应接近 100%）和能力套件（从低分爬坡）分开维护。
- eval 分数波动时先查用例是否不稳定，不直接改断言阈值。
