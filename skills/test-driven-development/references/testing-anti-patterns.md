# Mock 与测试反模式

> 编写测试、选择替身或调整测试边界时读取。测试范围与真实依赖策略由 [test-strategy](../../test-strategy/SKILL.md) 定义。

## Mock 准入（单点定义）

在获批替换边界使用替身：外部服务、数据库、时钟/随机源或文件系统等。不要替换当前被测行为的内部实现来制造通过，也不要为测试投机新建生产接口。“自己写的适配器”仍可能代表外部边界，按契约身份判断。

替身须覆盖消费者实际依赖的契约：字段、状态、错误、时序及副作用。没有被消费且不影响契约校验的可选字段不必全部复制；必需字段或验证器依赖的结构不可省略。不确定时查真实契约或样例，不能凭空补字段。

## 反模式 1：只验证替身存在

断言应能因目标行为出错而失败。结果/状态和交互都是可观察证据：次数、参数或顺序属于获批协议时可断言；仅证明 mock 按设置返回、或锁定私有协作者细节，没有证明业务行为。

## 反模式 2：测试侵入生产接口

不为测试单独暴露私有方法或新增无业务用途的生产入口。夹具准备和清理由测试工具承担；真实资源生命周期方法按实际生产职责判断，不能仅因测试也调用就删除。

## 反模式 3：替换掉所需副作用

先确认依赖的真实职责和测试需要的副作用。替换外部边界时保留该场景所需的状态变化、错误和回调语义；替身绿不证明真实依赖的集成行为。

## 反模式 4：契约不完整或过度复制

用当前公开契约覆盖本场景实际消费的字段和分支；不要省略依赖字段，也不要复制整套 SDK/服务实现。需要验证真实序列化、存储约束或事务时使用对应适配器集成测试。

## 反模式 5：补测冒充测试先行

如实区分先行红绿、既有实现补测与纯重构刻画；处理方法见 [TDD 入口](../SKILL.md#既有实现的补测恢复)。不能修改日志、回填时间或用隔离前态的失败伪造原开发顺序。

## 反模式 6：同义反复

期望值来自契约、独立手算或其他可靠真值，不用被测算法再算一次 expected。例如求和样例 `[2, 5, 8]` 直接断言 `15`，而不是复制同一 reduce 表达式。

## 反模式 7：实现耦合与越过接口

在获批 seam 观察行为。公共行为未变但私有重构弄坏测试时，修正测试落点；公共行为回归时修实现。测试声称覆盖 HTTP 却只查内部表不足以证明响应契约；批准的数据库适配器测试则可以直接验证真实 DB。夹具准备和清理不是旁路行为断言。
