# 契约不变修复的守卫处理

> 阅读时机：改动命中 active spec 的 covers、且契约不变时，在首次受影响的编辑或提交之前读取。

### 步骤 5b：按是否命中 covers 选择提交路径

强制 TDD 同 5a。契约没变时不伪造 spec 修改；"契约不变"这个判断本身不产生新的授权。

| 情况 | 编辑与提交路径 |
|---|---|
| 没命中任何 active spec 的 covers | 普通编辑和提交 |
| 命中 covers，契约不变，且用户已授权例外 | 用 `SPEC_DEV_GUARD=off git commit` 放行提交时的检查，同时在提交信息里留 `Spec-Guard: off <原因>`，供推送和 CI 的区间检查核验 |
| 命中 covers，契约其实变了 | 回到 5a，同一提交里同步 spec |
| 命中的是另一个特性的 spec，影响不明 | 停下，交用户裁决或按升级门处理 |

环境变量只影响带着它运行的那条 `git commit`；`Spec-Guard: off` trailer 才会被推送和 CI 的区间检查识别，两者不能互相替代。

编辑时的拦截（宿主的编辑前 hook）由宿主进程的环境决定，给写入命令加 off 前缀影响不到它。只在用户已授权例外时，选择会话或 hook 层的临时关闭，用完撤销；没有授权先说明原因并取得裁决。

**不静默绕过、不伪造 spec 同步。**
