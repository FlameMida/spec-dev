# 验证归属与按影响复验

> 阅读时机：生成任务测试范围、修复失败、复用证据或最终验收时。此处统一范围规则，原始回执格式仍归 writing-plans/plan-format。

## 三个独立问题

1. **必需程度**：矩阵 `required` 决定能否整体通过，耗时长/需要人工不等于可选。必需项 fail 阻塞，warn/unverified/manual-pending 保持未完成；延期或放弃沿用户明确裁决，不由执行者改为 optional。
2. **执行时机**：任务内目标测试、最早可运行切片的真实集成/页面检查、最终 F 完整回归。fast/final/manual 是调度归属，不能把 final 理解成所有真实集成都只能末尾运行；明确属于任务目标的真实验证在该票执行，不把局部目标称为 F 完成。
3. **执行条件**：真实账号、外部写入、费用和环境沿已有授权判断。manual 需要明确执行授权，获批计划中同范围授权可复用；条件缺失时记录 pending，不因缺条件伪造通过，也不重复索取已有授权。

## 失败分类与复验表

先识别首个失败属于产品、测试helper/fixture、环境还是前置失败导致的级联。修复有因果证据后，再判断哪些原件失效。不能把级联数量当独立缺陷数。

| 实际改动 | 默认受影响范围 | 扩大条件 |
|---|---|---|
| E2E 定位器、等待 helper | 使用该 helper 的场景与相关视口 | 改动公共 runner、认证 fixture、数据准备或发现跨场景影响 |
| 页面布局、交互 | 相关组件、实际页面、受影响状态/视口 | 公共布局/导航/权限入口影响其他页面 |
| 后端业务规则 | 对应公共用例、真实集成、用户闭环 | 共享事务、协议、权限或跨模块依赖变化 |
| 公共鉴权、迁移、基础配置 | 实际依赖模块与集成，必要时完整套件 | 明确影响链或无法界定的真实共享影响 |

核验 argv/cwd/退出码、原件 hash、代码/断言/fixture/配置/spec 与环境条件。记录哪些证据仍适用、哪些失效、为何选择本次命令。只改 helper 不自动使 Go 全量失效；文件不相交也不自动证明独立。旧回执的机械范围过宽而无法通过版本核验时，保留未确认，不伪改 scope；为后续检查使用获批且足够覆盖依赖的精确范围，不能事后缩窄来转绿。

首次 F 执行项目完整套件，修复后的新候选补验真实影响、复审受影响维度并更新验收/对账。要求完整重跑须说明当前影响理由或引用用户明确要求；不写“一处修改即全部重跑、不省步骤”的无条件指令。新失败/新影响是扩大检查的依据。

## 最早真实闭环

计划指出第一条真实用户流程在哪一票形成及必要前置。该票完成时验证入口、角色、页面、实际服务及持久结果；边界替身沿已批准范围，原型模拟成功或传输替身不能冒称真实闭环。UI 同时对照定稿 HTML 的适用状态；工程证据和界面证据分别保存，最终验收直接消费仍适用的原件。
