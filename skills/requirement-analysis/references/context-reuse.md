# 概念、否决与共享术语复用

本文件是路由前双查、概念级否决记录和仓库共享术语的单点定义。入口只给用途摘要与指针，不复制规则。

这里的仓库指用户项目：项目 `.spec-dev/` 及其产物引用在用户项目中解析，不在插件规则目录中解析。先核实用户项目根，不能把规则文件所在仓库当成用户产物根。

## 路由前双查

RA、quick-fix 与 triage 提议路线前，按当前问题限定范围：先用领域概念及已确认别名核查已有实现，再查相关 .spec-dev/explorations/ 笔记中的历史否决。已有实现报告位置和适用边界，不能写成否决；历史否决报告原理由、用户决定来源及适用条件。条件改变、新证据或用户改判可重新讨论，命中记录不自动拒绝请求。

先读适用域相关的 .spec-dev/glossary.md（存在时）帮助按概念查询。结果保留概念、检索范围、实现指针、相关否决及未核查范围。没有仓库或文件时如实说明，读取失败不当作查无记录，不要求全仓穷举，不为双查创建文件。显式 skill 选择及同范围已有决定直接消费，不重复路由确认；原有建议式路由不变。

复述旧值或旧决定前先取得对应记录；把历史事实、本轮给定事实和待查假设分开，不能用当前预算等不同角色的数字补出旧报价。

历史排除与本轮重开分别核对：
- **历史排除背景**：原记录的理由和适用条件描述当时为何排除。按原义转述，不将这些字段改称记录设定的“重新讨论条件”，也不把原条件满足写成才可或才需重审的前提。
- **本轮重新讨论**：依据用户当前请求或新事实推进；用户明确要求重开时，旧条件未变也直接继续讨论。条件变化或新证据同样可以成为讨论依据，不把当年的排除决定当作永久禁谈。

最终结论与交接中的历史段落也按这两个不同问题核对：保留当时的排除背景，不把本轮的建议或新条件归于旧记录。重新讨论本身不等于批准实施。

## 否决记录

exploring/clarifying 获准保存笔记时，将已排除概念单列为「已排除选项」：概念、理由、用户决定来源、适用条件。未决问题仍单列；条件变化时追加重开说明，保留原决定，不覆盖历史。不新建否决知识库目录，不把已实现能力记成否决。未获保存授权只在对话保留。

## 共享术语

讨论前读取适用域的 `.spec-dev/glossary.md`。位置、内容形状、保存授权、冲突和 ADR 规则的唯一完整定义见 [跨技能文档规范](document-conventions.md)，实际文档动作前取得全文；已有当前定义不重读。
特性局部术语留对应 spec；同范围已批准决定直接消费，不因新会话重问。
本文件的路由前双查、历史否决和事实来源纪律继续适用。
