# 共享探索入口
> 阅读时机：RA/exploring 首次材料读取或提问前；当前定义已取得则复用。

先核对当前问题、已知授权与材料归属。用户项目与插件规则目录不是同一个根。
内部代码的定向调查不强制加载外部研究和代理恢复全文。
第三方依赖、服务和标准的事实，即使材料位于本地，仍按外部事实处理。
事实、引用和推断分开；不把源码静态观察说成已经运行验证。
普通提问消费 [clarifying](../../clarifying/SKILL.md) 的当前核心纪律。
外部研究在读取材料前取得 [来源纪律](../../../agents/external-resource-explorer.md)。
准备派发、接管或恢复代理前取得 [派发与恢复](agent-dispatch.md)。
使用插件内命令前取得 [插件根解析](plugin-root.md)，路径先解析为实值。
接收需契约校验的结果前取得 [输出契约](output-contracts.md)。
现行汇总入口 [exploration-patterns.md](exploration-patterns.md) 继续有效。

每个动作只加载适用专题，但必须在动作发生前取得完整定义。
当前上下文中已有相同有效定义就复用；新 worker 不以主线程曾读代替自己取得。
主题范围、用户预算和访问权限不因加载规则而扩大。
适用定义或引用缺失时报告具体缺口，不静默绕过；无关专题不因存在而变成必读。

## 技能定义与流程调用

跨技能动作先区分用途，按当前宿主实际能力取得规则：

- **介绍或路由建议**：提到技能名称不等于要求执行，不因报告或菜单列出它就启动其流程。
- **引用纪律**：直接引用完整专题时读取该专题；引用某技能的纪律时取得其正文及当前动作必需的参考，消费被引用模式。仅名称、description 或摘要不能代替规则。不把专题引用变成完整流程转交，也不因读取 clarifying 就添加独立开场或三出口。当前上下文已有相同有效定义时复用，不为形式重复加载。
- **实际流程转交**：沿用户已有同范围授权、目标技能准入及宿主调用策略执行。有原生加载工具时使用实际接口；没有工具但定义可读且策略允许时，按会话技能目录指向的文件或资源提供方取得正文，再遵循获准流程。不得虚构工具调用、只凭 description 行事，或把“已加载”报告成“已执行完成”。
- **调用限制与缺失**：明确仅用户可触发的目标，不能通过读取文件自动进入；确需该流程且当前请求未覆盖时，说明所需的具体入口。先核对技能目录和实际可读来源，再判断是否缺失；不可取得的必需规则只阻止依赖该规则的动作，不用猜测内容代替，也不新增自动安装或配置修改。

多个依赖按实际接口分别处理；工具一次只接受一个技能名时，不将两个名字塞进同一参数。规则已取得、事实查询、保存、实施及外部写入是不同动作；加载不扩大授权，也不重复索取已有同范围许可。
