# 跨技能文档规范
> 阅读时机：读取、创建或更新共享术语和 ADR 前；已有当前定义可复用。
> 所有技能，包括独立 DDD 与被调用 DDD，使用本文件的同一套规则。

## 文档位置
- 跨特性领域术语：用户项目 `.spec-dev/glossary.md`。
- 本特性局部术语：对应 spec 的术语节；无适用 spec 时先保留候选，不自动启动完整特性。
- 架构决策：用户项目 `.spec-dev/adr/`，全项目统一编号和生命周期。
- 同名不同义概念以适用域区分，不强制跨域只有一个定义。
- 用户明确位置要求优先；无覆盖指令时不因技能独立调用而改用另一套默认位置。

## 保存授权
完整设计获批或用户明确批准当前文档保存范围后才写入。
术语已讨论清楚本身不是文件写入授权；批准前留在对话候选中。
同范围既有明确授权直接复用，不逐个术语或 ADR 重新询问；新范围仍先明确。
只授权术语保存不等于批准新行为义务、实现策略或自动创建 spec/plan。
只读讨论和用户明确禁止写入的约束优先。

## 旧位置与来源
已有 CONTEXT.md、docs/adr/ 或其他词汇表不自动迁移、删除或双写。
在当前获授权任务中遇到冲突时展示实际来源与差异，按现行裁决处理。
不为统一新规范主动扫描、重写历史文档。
没有内容不创建空 glossary；ADR 三条件不满足不创建空 ADR。

## 共享术语

进入相关讨论时，RA、quick-fix、triage、exploring 和 clarifying 读取适用的仓库 .spec-dev/glossary.md。只收跨特性复用的项目专有概念，不收通用编程术语；本特性局部概念留在 spec。记录形状：

- **规范名**：一两句定义。_Avoid_：别名（无则写无）。适用域：具体领域。来源：对应获批设计/用户裁决的可恢复指针。

同名不同义先展示定义、域和来源，逐题由用户裁决；跨域可并存，不强行全局唯一命名。glossary 与现行 active spec/Accepted ADR 矛盾时点明冲突，沿现有契约姿态及取代流程处理；词汇表不自动推翻合同、不触发全仓旧术语替换，也不参与守卫解析。

所有调用方按本文件「保存授权」及本次角色的更具体限制判断写入权限；triage 始终零落盘，独立 exploring/clarifying 仍沿明确的保存出口或已有授权。首次没有共享术语不建空文件，局部术语留对应 spec。实际保存失败报告错误及待保存内容，不宣称成功。文档保存授权不扩为实施授权。

保存内容限于已批准设计。实际写入或提交前，以将保存的最终 spec/glossary 正文及 frontmatter 为对象，逐项对照本轮批准来源：核对新增行为义务、接口结果、已确认决策和取代声明，不只核对文件名、格式或提交范围。仅术语的设计只记录定义、适用域、Avoid、来源及必要概念说明，不把模板空节补成运行时 SHALL、实现策略或 supersedes。尚未获批的行为留待后续设计，不固定在本次稿件；共享记录不扩大原设计范围。

讨论备选方案时区分现行定义与拟议变化：同名状态或概念若改变了成立条件、适用域或保证，明确指出差异并保持待裁决，不能仅因名称相同就称为保留现有语义。提出新方案本身不改写旧契约。

在方案比较中声称概念或状态的语义保持不变之前，对照已读契约核对原成立条件、拟议成立条件及各自的保证；选项标题和最终推荐摘要同样核对，不能前文说明变化、后文又归称为旧语义。若仅名称或返回形状未变，就明确保留的是这一层，不把新增联网、外部确认等前提说成旧契约自带。

后续阶段消费既有定义及决定来源；没有新冲突不重复确认。来源失效保留缺口，不自行补造决定。

## ADR 三条件与生命周期

- **决策分流（ADR）**：检查"已确认的关键决策"中是否有同时满足三判据的决策——**难以逆转**（事后改主意成本高）、**缺上下文会费解**（未来读者会问"当初为什么这么做"）、**真实取舍**（存在真正的备选且因具体理由选定其一）——满足者每条沉淀为仓库级 `.spec-dev/adr/NNNN-<slug>.md`（全项目共用一个目录、统一编号：扫描现有最高编号递增，目录不存在时随首个 ADR 创建；**落盘前重扫一次目录防撞号**——并行会话可能已用掉同号，发现同号文件已存在则顺延取下一号并同步修正正文与链接中的自引编号；正文 1-3 句写清背景、决定与理由即可，值得记住的被否方案附一行），spec 决策节保留一行摘要并链接过去；三判据缺一即不建 ADR——ADR 泛滥和没有 ADR 一样没用。**ADR 状态纪律**：每条 ADR 标题下带状态行，封闭三态——`**Status**: Accepted (YYYY-MM-DD)` / `**Status**: Deprecated (YYYY-MM-DD) — <一句原因，强制>` / `**Status**: Superseded by [ADR-NNNN](NNNN-<slug>.md) (YYYY-MM-DD)`（同目录文件名相对链接，编号强制；缺状态行的历史 ADR 视同 Accepted）。判据一句话：有替代决策用 Superseded，无替代者且决策语境消失用 Deprecated。Accepted 后正文不可变（仅 status 行、错别字、坏链可改）；**不做部分推翻**——推翻既有 ADR 的任何部分时，新 ADR 完整重述仍有效的结论并整体取代，标题下声明 `**Supersedes**: ADR-NNNN` 行，且在本阶段同一提交把旧 ADR 状态行回写为 Superseded by（ADR 取代随裁决即时生效，不等实施交付）
