# 跨技能文档规范

> 阅读时机：读取、创建或更新共享术语和 ADR 之前；本次会话读过就不用再读。
> 所有 skill 都用这一套规则，包括单独使用和被其他 skill 调用的 ddd-lifecycle。

## 文档位置

- 跨特性的领域术语：用户项目的 `.spec-dev/glossary.md`。
- 只在一个特性里用的术语：那份 spec 的术语节。没有对应的 spec 时先留在对话里，不为它新建特性。
- 架构决策：用户项目的 `.spec-dev/adr/`，全项目统一编号。
- 同一个名字在不同领域含义不同时，按领域分别定义，不强求全局只有一个定义。
- 用户指定了位置就按用户的；没有指定时，skill 单独使用也用上面的默认位置。

## 保存授权

用户批准了完整设计，或明确同意保存这部分内容之后才写文件；术语讨论清楚了不等于可以写。同一范围同意过一次就够，不逐条再问；范围变了重新问。同意保存术语只是同意保存术语，不包含新行为、实现方式或新建 spec 和计划。用户说只讨论不写文件时照办。

## 旧位置与来源

- 已有的 CONTEXT.md、docs/adr/ 或其他词汇表原样保留，不迁移、不删除，也不同时写两处。
- 当前任务里遇到新旧文档冲突时，把两边的出处和差异给用户看，由用户决定。
- 不为统一格式去扫描或重写历史文档。
- 没有内容就不建空的 glossary；不满足 ADR 三条件就不建 ADR。

## 共享术语

requirement-analysis、quick-fix、triage、exploring 和 clarifying 开始相关讨论时读 `.spec-dev/glossary.md`。词汇表只收跨特性复用的项目专有概念，不收通用编程术语。每条这样写：

- **规范名**：一两句定义。_Avoid_：别名（没有就写无）。适用域：具体领域。来源：对应的获批设计或用户决定，写到能找回原文的程度。

**冲突。** 同名不同义时，把各自的定义、领域和来源给用户看，逐个由用户决定；不同领域可以并存。词汇表与 active spec 或 Accepted ADR 矛盾时指出冲突，按 spec 的取代流程处理；词汇表不能推翻 spec，不触发全仓替换旧术语，也不参与漂移守卫。

**谁可以写。** 按上面的「保存授权」，再加各 skill 自己更严的限制：triage 始终不写文件；独立使用的 exploring 和 clarifying 只在用户选了保存时写。保存失败时报告错误和要保存的内容，不说成已保存。

**只保存批准过的内容。** 写入或提交前，把要保存的 spec、glossary 正文和 frontmatter 逐项对照本轮批准的内容：新增的行为要求、接口结果、已确认的决定、取代声明都要有出处。只批准了术语时，只写定义、适用域、Avoid、来源和必要的说明；模板里空着的节不要补成 SHALL、实现方式或 supersedes。没批准的行为留给以后的设计。

**沿用旧名字要说清变了什么。** 比较方案时，如果一个沿用旧名字的状态或概念改变了成立条件、适用范围或保证，要明确指出变了什么，交用户决定；标题和结论摘要里也这样写。只有名字或返回结构没变时，就只说这一层没变。

后续阶段直接使用已有的定义和决定；没有新冲突不再确认。出处找不到了就写明缺口，不自己补一个决定。

## ADR 三条件与生命周期

**什么时候写 ADR。** 检查“已确认的关键决策”，同时满足三个条件的才写：

1. 难以逆转：事后改主意成本高。
2. 缺上下文会费解：以后的读者会问“当初为什么这么做”。
3. 有真实取舍：确实有备选方案，并因为具体理由选了其中一个。

缺一条就不写。

**怎么写。**

- 位置和编号：`.spec-dev/adr/NNNN-<slug>.md`，全项目共用一个目录、统一编号。扫描现有最大编号加一；目录不存在时随第一个 ADR 创建。写入前重扫一次目录，同号已被占用（并行会话可能刚用掉）就顺延，并改正正文和链接里的编号。
- 正文：1 到 3 句写清背景、决定和理由；值得记住的被否方案附一行。
- spec 的关键决策里留一行摘要并链接到 ADR。

**状态。** 每个 ADR 标题下有一行状态，只有三种：

| 状态行 | 什么时候用 |
|---|---|
| `**Status**: Accepted (YYYY-MM-DD)` | 现行决定。没有状态行的旧 ADR 按 Accepted 对待 |
| `**Status**: Deprecated (YYYY-MM-DD) — <一句原因>` | 没有替代决定，决定所针对的情况已经不存在。原因必填 |
| `**Status**: Superseded by [ADR-NNNN](NNNN-<slug>.md) (YYYY-MM-DD)` | 有替代决定。链接用同目录的文件名，编号必填 |

**修改规则。**

- Accepted 之后正文不改，只能改状态行、错别字和坏链接。
- 要推翻一个 ADR 的任何部分，都新写一个 ADR：完整重述仍然有效的结论，整体取代旧的，在标题下加一行 `**Supersedes**: ADR-NNNN`。
- 新 ADR 和旧 ADR 的状态行改为 Superseded by 放在同一次提交里。ADR 的取代在用户决定时就生效，不等实施交付。
