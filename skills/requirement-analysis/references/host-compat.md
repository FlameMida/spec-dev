# 宿主适配

> 阅读时机：需要知道某个宿主具体用什么工具时。各 skill 正文只按能力描述，不写宿主专有的工具名；专有名称只出现在本文件。

各 skill 文首都带同一段话，本文件是它的定义点：

> **宿主适配**：提问用宿主的提问工具，没有就发普通消息并停下等回复；有子代理能力才派发，没有就由主线程完成并注明；进度工具可用可不用，以落盘文件为准；需要其他 skill 时按名称加载，加载不到就读同级目录下的 `SKILL.md`。

## 按能力降级

| 能力 | 有的时候 | 没有的时候 |
|---|---|---|
| 向用户提问 | 用宿主的提问工具 | 发普通消息并停下等回复；无人值守拿不到回复时按未同意处理 |
| 子代理 | 派通用子代理，派发词里给出 brief 文件的绝对路径并要求先读 | 主线程完成，并在结果里注明不是独立执行 |
| 进度工具 | 可用可不用 | 以落盘文件为准（计划的复选框、spec、执行记录） |
| 隔离工作区 | 宿主已把会话放进隔离工作区就复用 | 用 `git worktree add`，命令用 `git -C <路径>`，文件用绝对路径 |
| 加载其他 skill | 按名称加载 | 读同级目录下该 skill 的 `SKILL.md` |
| hooks | 多一层提醒或守卫 | 规则都写在 SKILL.md 里，不依赖 hook 生效 |

skill 只依赖 `skills/` 目录里的文件。brief、模板和脚本都随 skill 分发；只装了 skills 的环境（没有插件的 hooks、命令和守卫脚本）也能完整走完流程。

## 各宿主的具体工具

| 用途 | Claude Code | Codex | 其他宿主 |
|---|---|---|---|
| 提问 | `AskUserQuestion` 或对话 | 可用的提问工具或对话 | 对话 |
| 进度 | `TaskCreate` / `TaskUpdate` | `update_plan` | 宿主自带的待办工具，没有就不用 |
| 子代理 | `Agent`（通用类型） | `spawn_agent`，需要结果时 `wait_agent` | 宿主的子代理能力；Pi 需要子代理扩展，没有就由主线程完成 |
| 项目规范文件 | 先 `CLAUDE.md`，再 `AGENTS.md` | 先 `AGENTS.md`，再 `CLAUDE.md` | 先 `AGENTS.md` |
| 搜索 | anysearch skill，降级到内置搜索 | anysearch skill，降级到内置搜索 | anysearch skill，降级到宿主搜索 |

无法判断宿主时，按"没有的时候"一栏行事。

### 子代理的注意点

- 不假设子代理会自动加载任何定义文件。派发词里必须写明要读的 brief 的绝对路径、有界的主题、完成条件和只读要求。
- 需要独立判断的子代理（审查 spec、审查代码）不继承主会话的上下文。Codex 的 `spawn_agent` 用 `fork_turns: "none"`；旧版本的参数是 `fork_context: false`，其中一套被拒绝就换另一套。
- 子代理失败或没完成：先缩小范围重试 1 次，再失败由主线程接管。平台标记完成不代替对结果的判断。
- 主线程明显降质（反复遗忘既定结论、同一个错误反复出现、上下文告急）时，在最近的阶段边界把产物落盘并提交，再继续或重开会话。

### Codex

- 沙箱默认禁网时，搜索工具都不可用就降级为 `rg` 加本地文件阅读，并告诉用户。
- workspace-write 沙箱里一般可以直接 `git commit`，但 `.git/hooks/` 和 `.codex/` 只读。提交因沙箱策略失败时，请用户授权或自行提交，文件照常落盘。
- visual-preview 的服务器脚本会检测 `CODEX_CI` 并自动切到前台模式。

### Grok Build 与 Pi

- Grok Build 复用 Claude 的清单；它的 SessionStart 不向模型注入上下文，所以流程规则不能依赖 hook 提示。
- Pi 只分发 skills，没有 hooks；子代理需要扩展。

### 插件命令

`/doctor`、`/status` 这类插件命令要定位插件安装目录，规则见 [插件根解析](plugin-root.md)。skill 本身不需要它。
