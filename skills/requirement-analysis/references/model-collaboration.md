# 非 Claude 模型协作增强

仅在**本代理**当前收到 `spec-dev collaboration: enabled` 时应用；`disabled`、模型未知或只有父代理的状态时不启用。按实际模型而非宿主判断；Claude Code 中的 Kimi/GLM 同样适用，Claude 模型排除。切换模型后以本代理最新状态为准，历史增强文本不能继续作为生效依据。子代理只对获派范围负责，不接管主线程目标或扩大写集合。

本文件是增强行为的单一定义点。它补充现有阶段，不增加流程、固定表格或审批门；明确的用户约束、设计批准、契约变更、任务绑定、TDD 和发布授权仍按原规则执行。分析、审查、探索请求的完成物就是对应分析，不自行转为实施。

## 目标与必要工作

接到方向后先查请求、代码、现有契约及已确认决定，形成简短的目标结果、必要工作与完成证据、边界、关键假设。由代理起草，不要求用户逐项列清单；两三句话说明后继续已授权工作，不把复述变成等待批准。

用户明确要求的内容全部保留。对未列出的工作，判断省略后是否使目标不成立、正常使用受阻或破坏既有契约；必要且已授权的主动补齐。“有帮助”不等于必要，新独立能力与重大方案变化先说明依据和取舍。必要性不提供额外授权；需要变更 spec、计划或 writes 时先走已有偏差和绑定规则。

## 决策筛选与动作依据

准备提问时，依次检查可查事实、已有决定与有效授权、项目惯例及合理默认值。目标范围内普通可逆的实施选择自行处理，重要假设简短说明并标为代理选择；剩下会实质改变交付、重大取舍或授权的事项才沿 clarifying 提问。已经确认的决定直接消费，推荐和沉默不是批准。

检查用户方案的前提，区分事实、推断和假设；有证据时提出异议并给出推荐。信息足够就行动，不重论已定事项；用户了解顾虑后重申选择就继续，只有新关键证据或用户要求才重开。修复、重启、删除和配置修改前，证据须支持具体动作；仅症状相似时先做能区分原因的检查，不套用熟悉修法。

## 持续执行与恢复

复用 spec 的目标/边界/决定、plan index、progress 的 current/tasks/notes 和已有证据维护状态；普通任务留在对话，不另建目标台账。用户补充默认并入原目标，明确取消、缩小或改向及时生效，不让最新问题挤掉其他要求。

阶段结束、重要新证据、压缩恢复及交付前对照原目标、有效决定、完成证据、剩余工作和下一步。沿当前阶段重新取得适用规则与记录，不重做已完成调查；进度询问回答后继续原任务。

局部阻塞只冻结依赖它的工作；按现有依赖图、写入/资源边界及授权继续独立部分，不重排活动 claim 或绕过串行恢复规则。无法安全假设或缺少必要授权时等待该部分，不能自行删减范围；所有剩余工作均无法推进时再整体等待。

## 交付前遗漏检查

按实际使用场景核对：还有什么阻止目标成立；原目标有哪些必要工作未做或未验证；证据支持多大范围的结论；是否有需要用户再次提醒的收尾。完成条件对应现有证据，不把计划勾选、局部测试绿或预算耗尽当作完成。

检查最后答复中的“下一步”“可以继续”“我将”：若指向原请求中已授权、现在可完成的必要工作，就继续执行，不能改称可选建议。确实受阻时说明未完成内容、已尝试路径和解锁条件。最终答复独立说明结果、验证及实质缺口，无需用户翻看中途消息。
