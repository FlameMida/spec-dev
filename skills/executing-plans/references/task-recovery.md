# 任务恢复

> 阅读时机：首次执行、任务边界、会话恢复或处理集成组之前；上下文压缩后从磁盘重新读取适用规则，不能只凭摘要恢复。

仅本代理当前 `spec-dev collaboration: enabled` 时，同时复核 [模型协作增强·持续执行与恢复](../../requirement-analysis/references/model-collaboration.md#持续执行与恢复)；不能沿用父代理或切换模型前的启用状态。

绑定或写入前读取 [worktree 工具与命令边界](../../using-git-worktrees/references/tool-boundaries.md)。核对工具真实 cwd、当前绑定与执行记录，区分文件缺失、宿主执行前拒绝和绑定校验失败；人工回执不证明自动绑定已恢复。

## 串行续接

1. 读取单文件计划与关联 spec，核对已有授权、稳定 TNN、复选框与执行记录。未勾选步骤只是候选，不能当成授权；多个未完成任务且无法定位当前任务时报告具体缺口。
2. 沿执行记录中的工作区管理方式恢复：Git 创建的工作区通过实际 cwd 续接，宿主原生工作区沿原入口恢复。核对来源/实施根、分支、当前 tip、dirty 与资源归属；不自动切换仍在运行的隔离会话。
3. 逐项对照完成记录、真实提交与验证原件；已验收并记明 execution 已清理的任务，核对摘要和受测版本，不把按规则删除当新证据缺口或重跑理由；提交存在不表示验证及状态保存已完成，目录消失不证明已清理。当前任务有阻塞先处理阻塞；无当前任务才取依赖已完成的最小编号任务。集成组按下节处理。
4. 按 [绑定协议](../../writing-plans/references/plan-format.md#绑定与激活唯一定义点) 核对并激活当前范围。步骤完成后先 clear，再保存已有 SHA、原件引用与复选框并窄提交。契约级偏差冻结受影响后继，沿主流程修订，不扩大 writes。

不重做已证实完成的任务；证据缺口或候选变化按 test-strategy 补验。已合并但未收尾的计划只继续交付；全部完成的档案只读核验。

## 集成组恢复

状态与步骤沿 [任务模板](../../writing-plans/references/task-templates.md#单文件中的纯重构与集成组)。进入前核对整组全部外部前置，不以组首单票可执行代替。主线程串行执行成员，保存待验 SHA、可运行检查及未勾选的组验证项；意外失败保留原件并阻塞，不能勾选完成。

恢复先核对待验提交、阻塞点与原件，续接未完成成员；所有成员就绪才运行统一验证。失败回到负责成员修复并补验受影响依赖；通过后才完成全组并解锁组外。统一组验证不能替代独立 final 或 acceptance-qa。
