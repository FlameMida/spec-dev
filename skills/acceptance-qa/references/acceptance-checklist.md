# 验收清单

> 阅读时机：生成或核对验收清单时。清单在需要验收的那一刻按实际改动生成，不在 spec 阶段预先填写。

## 结构

```markdown
| 行为 / 检查项 | 怎么看 | 预期 | 方式 | 状态 | 证据 |
|---|---|---|---|---|---|
| 正确凭据登录后跳转仪表盘 | 打开 /login，输入测试账号，点登录 | 跳转到 /dashboard 并显示用户名 | 代验 | pass | 截图 login-01.png |
| 拒绝过期 token | `curl -H "Authorization: Bearer <过期>" /api/me` | 返回 401 与 `token-expired` | 自己验 | 未执行 | — |
| /api/login p(95) < 300ms @ 50 VU | k6 smoke | THRESHOLDS 全部通过 | 不验 | 未执行 | — |
```

- **行为 / 检查项**：优先直接用 spec 里 Scenario 的名字；性能、视觉这类非行为项写成一句可判定的话。
- **怎么看**：可复制的命令，或具体的操作步骤。用户选"自己验"时，这一栏就是交给用户的全部内容，要写到照着做就能看到结果。
- **预期**：可观察的结果。性能项必须带阈值数字，写不出数字就先问用户。
- **方式**：自己验、代验、不验，由用户逐项选择。
- **状态**：`pass | warn | fail | unverified`；用户没选代验的项写"未执行"。
- **证据**：原始输出、截图或 trace 的位置。"操作过了"不算证据。

一行只验一件事。

## 怎么生成

1. **从 Scenario 生成**。每个现行 Scenario 一行：GIVEN 和 WHEN 变成"怎么看"，THEN 变成"预期"。已被取代的 Requirement 不出行。
2. **按实际改动补推荐项**，并在给用户的话里说明理由：
   - 改了页面：对照定稿和组件映射表看页面，补适用的异常状态（加载、空数据、错误、无权限）。
   - 改了接口：实际调用一次，核对状态码、响应字段和副作用。
   - 改了数据迁移：在测试库上演练迁移与回滚。
   - 改了性能敏感路径且有预算：补性能项。
3. **没有 spec 时**从目标描述生成：按真实流程和状态提取功能要点逐条成行，再挑适用的通用项（页面跳转正确、加载反馈、无明显视觉异常、无 console 错误）。

## 维度取舍

| 需求形态 | 默认纳入 | 默认不纳入 |
|---|---|---|
| 纯后端接口或服务 | 接口行为、有 SLO 时的接口性能 | 浏览器 E2E、视觉、可访问性 |
| Web 界面功能 | E2E、视觉、可访问性 | 接口性能（除非同时改了接口） |
| 首屏或加载体验 | 页面性能、视觉 | 接口性能 |
| 桌面或移动客户端 | 对应环境的 E2E、视觉 | 页面性能 |
| 纯样式或文案调整 | 视觉、可访问性 | 接口行为、性能 |

没纳入的维度和理由写进报告，让用户看得到"验了什么、没验什么"。

## 整体结论

有 fail 即失败；有 warn 或 unverified 即未完成；全部选中项 pass 才算通过。结论只覆盖用户选中并实际执行的项，其余如实写"未执行"。确认过的局部预览不等于业务交付；不用单测数量或新的截图基准代替与定稿的对照。
