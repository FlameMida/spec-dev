# E2E 验收（D 确定性）

> 明确要跑 E2E 或补写确定性用例时读取。页面验收的主流程在 SKILL.md；本页不要求每次验收都装 Playwright 或新建测试工程。

## 工具与范围

用目标项目已有的测试运行器、配置、测试目录、包管理器和命令；monorepo 在实际的项目根执行。项目没有 E2E 配置时，先确认这次选中的检查是否真的需要 E2E、有没有现成的脚本或夹具可用，再在已获同意的范围内补齐。

记录实际的入口、角色、数据、视口和状态。每个用例至少有一条业务断言，目标功能坏了它就会失败。页面打得开、元素可见、返回成功状态码，都还不能说明保存、权限或持久化是对的。用了网络替身的用例只证明替身覆盖到的本地行为；真实的端到端结果要用真实后端另外验证。

## 定位与等待

- 定位元素优先用用户能感知的 role、name、label，或项目已有的 test-id 约定；项目没有 `data-testid` 约定时不必为此新增。
- 少依赖容易变的 CSS 和 DOM 细节。文案本身是要验的内容时可以断言它。
- 等待用定位器自带的自动等待和可重试断言，等的是这个场景里可以观察到的结果；需要时关联具体的请求、响应和随后的业务结果。
- 固定 sleep 和 `networkidle` 不能说明业务已经完成；页面有长连接也不代表失败。

以上与 Playwright 的[定位与断言建议](https://playwright.dev/docs/best-practices)及[加载状态说明](https://playwright.dev/docs/api/class-page#page-wait-for-load-state)一致。语法和版本能力按项目实际安装的版本查。

## 数据与替身

- 认证和数据准备用项目已有的方式。凭据通过现有的安全配置提供，不写进测试源码或报告。
- 每次运行用可识别、可清理的数据，结束后只清理自己创建的。
- 文件、数据、账号和服务资源确实互相隔离时才并行；同一个浏览器会话里的操作保持串行。
- 网络拦截、fake 和录制回放只用在获准替换的边界上，报告里写明它覆盖了什么、还缺哪些真实集成的证据。替身返回成功不能盖住真实后端的失败；前端的成功提示不能当作数据已保存的证据。
- 新窗口、iframe、上传和桌面客户端按宿主实际能力操作；进不去的部分标为未验证，外层截图不能代替里面的交互证据。

## 生成与修复工具

已有的测试配置保持原样，不自动运行 agent 初始化。项目用了 planner、generator、healer 这类工具时，它们的产物同样要满足本页对断言和证据的要求。

healer 改过的 locator、等待、断言或 skip，要逐项经人确认后才计入验收，并核对原来的失败是否仍然测得到。已确认的产品缺陷不能靠 skip 或弱化断言变绿。其余没执行的项记 unverified；必需项没过，整体就不算通过。预期行为确实获准改变时，记下依据并重新建立对应的验证。

## 证据

保留实际的命令、退出码、原始输出和必要的 trace、截图，并说明每条断言验证了什么。偶发超时按实际样本诊断。“确定性”指结果由明确的断言判定，不保证浏览器或网络每次都没有波动。

原型还原、截图基线和可访问性扫描见 [visual-a11y.md](visual-a11y.md)，各有各的结论和范围。复验只补失效或缺失的证据，不靠缩小必需检查的范围来取得通过。
