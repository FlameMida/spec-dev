# 从 spec 到可并发任务图

> 阅读时机：按 spec 划分任务、修订依赖或评估并发潜力时。静态字段见 [计划格式](plan-format.md)，调度资格与资源字段见 [并发声明](parallel-declaration.md)；本页不新增协议字段。

## spec 给决定，plan 给可执行边界

先从已批准 spec 和现行代码提取下列内容。已有决定直接消费；会影响多个任务的未决语义先回主线程澄清并同步 spec，再定受影响的任务。不能把同一个未决问题分别交给 implementer 自行选择。

| 信息 | spec / 现行代码提供 | plan 落点 |
|---|---|---|
| 可观察行为 | 参与者、输入输出、错误与状态语义、范围外事项、Scenario | 每票交付行为及验证步骤 |
| 共享契约 | API/类型/数据结构、兼容与迁移顺序、跨模块不变量 | 四列导航和本票接口块：精确签名、约束与来源 |
| 测试边界 | 获批公共 seam、依赖替换边界、测试先例 | 本票 Scenario、实际测试代码和命令 |
| 实施边界 | 已有模块与必要前置调整 | 精确文件块、scopes 写集合、资源声明和依赖 |

spec 保留稳定的行为和设计决定；计划细化当前文件路径、代码片段与操作命令。共享契约须能通过 spec/index 和本票读取，不藏在另一票正文或聊天里；跨票传递沿 [测试落点的接口传递](plan-format.md#测试落点的接口传递)，不另建一份会漂移的接口清单。

## 先切出能完成的行为，再消除不必要的等待

1. **纵向切片**：每票完成一个可演示或可验证的行为，覆盖它实际需要的模块与测试。用户行为需要 UI、API 和存储时，优先用一条窄行为贯穿这些层，不先拆成全部后端、全部页面再串联。只有接口冻结、替换边界获批且能独立证明本票行为时，才单独拆页面或适配器；传输 fixture 的绿不能冒称真实组合已交付。无法独立绿的机械迁移按 expand→分批 migrate→contract，必要时沿集成组处理。
2. **辨认前置**：只有后票实际需要其代码/接口落地、数据迁移或安全顺序时，才建立依赖。必要的前置重构位于 T00 后的 T01；不为并发制造空抽象或无用途基础票。契约已写清并不表示代码已存在，实际导入或验证需要前票实现时仍须等它集成完成。
3. **处理共享写入**：盘点公共类型、schema/迁移、路由/导出注册、依赖清单/锁文件、生成物、测试夹具。按真实用途把公共前置集中给一个所有者，或把汇总注册放到依赖各切片的后置票；切片仍须能独立验证，后置票负责真实组合的验证。逐项核对职责说明与 scopes：若总导出已归汇总票，普通票不得又列它为 writes。共享 runner、根生成配置和公共 SDK 也按此检查；拆不开则保留实际冲突，不把同文件不同段落当作无冲突。
4. **最小依赖图**：逐边写明消费了哪个前序产出接口、真实验证前提或安全顺序。区分实施所需与最终接线所需：单票沿获批传输替换边界即可验证时，不因最终组合需要后端就自动阻塞整票；确实导入前票代码或需要真实发布数据时仍保留依赖。编号只用于导航和同等候选排序，不意味着 T03 必须等待 T02；“同一批”“同一里程碑”不构成依赖。仅争用同一文件/数据库时用写集合或资源排他表达，不为此伪造语义依赖。传递冗余边可以简化，但删掉它们不会增加实际并发。
5. **证明隔离**：scopes 包括测试和工具实际会改的文件；外部数据库、端口、输出目录有真实隔离方案或排他资源键。独立 worktree 只隔离文件，不隔离共享服务。mock 只用已批准的替换边界，不能为凑并发新增 fake 或把真实组合验证删掉。

如果某票仍需猜测兄弟票的内部实现、同时编辑公共契约，或只能等未声明的另一票才能验证，就尚未准备好独立派发。回到边界和依赖修订，不要求执行器在派发时临时补设计。

## 把判断交给执行入口

在 index 全局约束附近写简短「并发准备」说明（说明文字，不是新状态表）：

- 共享契约与 seam 的来源，以及共同前置如何交付。
- 可重叠的任务链、每条必要依赖的理由；可用小型依赖图说明，四列导航仍为依赖权威。
- 共享写入的所有者、资源隔离办法、必须主线程执行的票；不能并发时写具体原因。

交接前在几个能改变 frontier 的完成点走查实际可同时运行的票：先按依赖找 ready，再扣除写集和资源冲突。简短说明哪几票能重叠、哪些仍会互斥及具体原因；不要把 ready 数、worktree 数或 parallel 声明当作实际并行数。这是 index 的准备说明，不新增运行时状态源；纯依赖链如实写逐票运行，不为凑并发拆空票。

然后按 [并发声明](parallel-declaration.md) 填现有块：writes 只在 scopes，parallel 列出所有合格票的 resources，包含需要等待前置的票；没有独立分支也按链声明，不为证明并发制造空任务。纯重构、授权例外、空基线、集成组和生命周期票沿既有主线程分流。完成 Self-Review 和 plan-index 校验后才交接；执行获准后默认使用这张任务图，无需再选并发。

示例：已有导出器扩展点，CSV/JSON 都能独立运行和测试；只有真实的格式注册需要汇总。下面展示依赖关系，具体路径、签名和命令仍由实际任务提供：

```text
T00 隔离 ──→ T01 必要的共享接口调整
                  ├──→ T02 CSV 导出 ──→ T04 CSV 流式处理 ──┐
                  └──→ T03 JSON 导出 ──────────────────────┤
                                                       T05 注册与组合验证
                                                         ↓
                                                       F → 审查 → A/对账 → D
```

T02/T03 依赖 T01；T04 只依赖 T02；T05 依赖 T03/T04。T02 集成验证完成后，只要容量与资源允许，T04 可在 T03 尚未结束时启动，不人为等待“这一批全部完成”。若 T04 与 T03 争用同一测试库，则暂缓 T04 或在计划中提供真实隔离；不能删除真实依赖、凭声明猜测隔离或越过主线程专属票。
