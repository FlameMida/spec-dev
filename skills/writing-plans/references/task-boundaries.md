# 从 spec 到任务边界与真实依赖

> 阅读时机：按 spec 划分任务或修订依赖时。静态字段见 [计划格式](plan-format.md)；本页不新增协议字段。

## spec 给决定，plan 给可执行边界

先从已批准 spec 和现行代码提取下列内容。已有决定直接消费；会影响多个任务的未决语义先回主线程澄清并同步 spec，再定受影响的任务。不能把同一个未决问题分别留给后续任务自行选择。

| 信息 | spec / 现行代码提供 | plan 落点 |
|---|---|---|
| 可观察行为 | 参与者、输入输出、错误与状态语义、范围外事项、Scenario | 每票交付行为及验证步骤 |
| 共享契约 | API/类型/数据结构、兼容与迁移顺序、跨模块不变量 | 四列导航和本票接口块：精确签名、约束与来源 |
| 测试边界 | 获批公共 seam、依赖替换边界、测试先例 | 本票 Scenario、具体输入/动作/断言与运行命令 |
| 实施边界 | 已有模块与必要前置调整 | 精确文件块、scopes 写集合、资源声明和依赖 |

spec 保留稳定的行为和设计决定；计划细化当前文件路径、改动要点与操作命令，片段按需提供。共享契约须能通过 spec/计划头部 和本票读取，不藏在另一票正文或聊天里；跨票传递沿 [测试落点的接口传递](plan-format.md#测试落点的接口传递)，不另建一份会漂移的接口清单。

## 先切出能完成的行为，再确定真实前置

任务是携带独立测试周期、值得独立审查的最小单元；只在审查者可能拒绝一票而通过相邻票处切分。配置、脚手架和文档折叠进使用它们的任务；无 UI 的行为不强加 UI。

1. **纵向切片**：先指出第一条真实用户闭环的任务号、实际入口与必要前置；该票验证适用原型状态及真实业务结果，不等汇总票才首次体验。每票完成一个可演示或可验证的行为，覆盖它实际需要的模块与测试。用户行为需要 UI、API 和存储时，优先用一条窄行为贯穿这些层，不先拆成全部后端、全部页面再串联。只有接口冻结、替换边界获批且能独立证明本票行为时，才单独拆页面或适配器；传输 fixture 的绿不能冒称真实组合已交付。
2. **辨认前置**：只有后票实际需要其代码/接口落地、数据迁移或安全顺序时，才建立依赖。必要的前置重构位于 T00 后的 T01；没有实际阻碍不造空重构、空抽象或无用途基础票。契约已写清并不表示代码已存在，实际导入或验证需要前票实现时仍须等它集成完成。
3. **处理共享写入**：盘点公共类型、schema/迁移、路由/导出注册、依赖清单/锁文件、生成物、测试夹具。按真实用途把公共前置集中给一个所有者，或把汇总注册放到依赖各切片的后置票；切片仍须能独立验证，后置票负责真实组合的验证。逐项核对职责说明与 scopes：若总导出已归汇总票，普通票不得又列它为 writes。共享 runner、根生成配置和公共 SDK 也按此检查；拆不开则保留实际冲突，不把同文件不同段落当作无冲突。
4. **最小依赖图**：逐边写明消费了哪个前序产出接口、真实验证前提或安全顺序。区分实施所需与最终接线所需：单票沿获批传输替换边界即可验证时，不因最终组合需要后端就自动阻塞整票；确实导入前票代码或需要真实发布数据时仍保留依赖。编号只用于导航和同等候选排序，不意味着 T03 必须等待 T02；“同一批”“同一里程碑”不构成依赖。仅复用同一文件/数据库时记录共享写入和使用顺序，不为此伪造语义依赖。传递冗余边可以简化。
5. **核对资源边界**：scopes 包括测试和工具实际会改的文件；外部数据库、端口、输出目录写清实际归属、使用与释放方式。worktree 只隔离文件，不隔离共享服务。mock 只用已批准的替换边界，不新增 fake 或删掉真实组合验证来规避前置。

如果某票仍需猜测兄弟票的内部实现、同时编辑公共契约，或只能等未声明的另一票才能验证，就尚未具备可执行条件。回到边界和依赖修订，不把补设计留到执行时。

宽面机械迁移先尝试逐票独立验证；不成立时 expand 保留新旧形、按影响范围分批 migrate、最后 contract 删除旧形，每批通过相关验证再提交。连批次也不能独立绿时，记录证据，按真实批次保留小任务并声明集成组，待验、统一验证及失败恢复沿 [任务模板](task-templates.md#单文件中的纯重构与集成组)。

## 把判断交给执行入口

在计划头部简述共享契约与 seam 来源、每条必要依赖的理由、共享写入所有者及资源边界。按依赖由主线程串行推进，通过 Self-Review 后交接。

示例：已有导出器扩展点，CSV/JSON 都能独立运行和测试；只有真实的格式注册需要汇总。下面展示依赖关系，具体路径、签名和命令仍由实际任务提供：

```text
T00 隔离 ──→ T01 必要的共享接口调整
                  ├──→ T02 CSV 导出 ──→ T04 CSV 流式处理 ──┐
                  └──→ T03 JSON 导出 ──────────────────────┤
                                                       T05 注册与组合验证
                                                         ↓
                                                       F → 审查 → A/对账 → D
```

T02/T03 依赖 T01；T04 只依赖 T02；T05 依赖 T03/T04。主线程按依赖串行完成任务，同等就绪时取最小编号。即使 T03 排在 T04 前，也不添加没有实际消费关系的 T03→T04 边。共用测试库时先核对上票释放与清理，不能凭文件隔离猜测共享服务也已隔离。
