# 任务边界与依赖

> 阅读时机：按 spec 切任务，或修订任务依赖时。

## spec 给决定，计划给可执行边界

先从获批 spec 和现有代码取出下面的信息。已有的决定直接用；会影响多个任务的未决语义先回需求澄清，不把同一个未决问题留给各任务自行选择。

| 信息 | spec 与现有代码提供 | 计划里的落点 |
|---|---|---|
| 可观察行为 | 参与者、输入输出、错误与状态语义、Scenario | 每个任务的交付行为和测试步骤 |
| 共享契约 | API、类型、数据结构、迁移顺序、跨模块不变量 | 导航表和任务接口块里的精确签名 |
| 测试边界 | 公共入口、可以替换的外部依赖、既有测试先例 | 任务里的具体输入、动作、断言和运行命令 |
| 实施边界 | 已有模块、必要的前置调整 | 任务的文件清单和依赖 |
| 界面定稿 | 定稿 HTML 与版本、界面约定摘要、组件映射表、还原要点 | 头部的界面定稿，界面任务的界面还原和还原自查步骤 |

共享契约必须能从计划头部、本任务和依赖任务的接口行读到，不藏在另一个任务的正文里。

## 先切出能完成的行为，再确定真实前置

任务是带着独立测试周期、值得单独审查的最小单元。配置、脚手架和文档并进使用它们的任务；没有界面的行为不强加界面。

1. **纵向切片**。每个任务完成一个可演示或可验证的行为，覆盖它实际需要的各层。用户行为需要界面、接口和存储时，用一条窄行为贯穿这三层，不先做完全部后端再做全部页面。只有接口已经冻结、且本任务能独立证明自己的行为时，才单独拆页面或适配器。
2. **第一条真实闭环**。指出哪个任务让第一条真实用户流程跑通，把它尽量排在最前。替身通过不能冒充真实组合已经交付。
3. **真实前置**。只有后一个任务确实需要前一个任务的代码、接口、数据迁移或安全顺序时才建立依赖。必要的前置重构排在最前；没有实际阻碍就不造空的重构任务、空抽象或没有用途的基础任务。
4. **共享写入**。盘点公共类型、schema 与迁移、路由和导出注册、依赖清单与锁文件、生成物、测试夹具。把公共前置集中给一个任务，或把汇总注册放到依赖各切片的后置任务里；各切片仍要能独立验证，后置任务负责真实组合的验证。
5. **共享资源**。数据库、端口、输出目录等写清谁使用、何时释放。隔离工作区只隔离文件，不隔离共享服务。
6. **界面定稿**。spec 采纳了界面定稿时按组件映射表切：标为新增或扩展的封装组件并进第一个使用它的任务，被多个页面共用时单独成任务并排在前面。布局壳、令牌和项目还没有前端时的脚手架，并进打通第一条闭环的任务。不为每一屏单独拆任务。

某个任务如果还要猜兄弟任务的内部实现，或只能等一个没声明的任务才能验证，就还不具备执行条件，回去修订边界和依赖。

宽面的机械迁移按"先加新形、分批迁移、最后删旧形"切，每批通过相关测试再提交。连分批都无法独立通过时，合并成一个任务完成并验证。

## 示例

已有导出器扩展点，CSV 和 JSON 都能独立运行和测试，只有格式注册需要汇总：

```text
T01 必要的共享接口调整
  ├──→ T02 CSV 导出 ──→ T04 CSV 流式处理 ──┐
  └──→ T03 JSON 导出 ─────────────────────┤
                                       T05 注册与组合验证
```

T02 和 T03 依赖 T01；T04 只依赖 T02；T05 依赖 T03 和 T04。T03 排在 T04 前面，但两者没有消费关系，所以不加 T03 到 T04 的依赖。执行时按依赖推进，同样就绪的取编号最小的。
