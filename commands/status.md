# 状态概览

按[插件根解析](../skills/requirement-analysis/references/plugin-root.md)确定插件目录，运行 `node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs"`。工具 shell 受 RTK 规则约束时加 `rtk proxy`。cwd 是用户项目。

| 需要 | 加参数 |
|---|---|
| 查看指定的仓库 | `--repo "<目标路径>"` |
| 机器可读的输出 | `--json` |
| spec 与计划的提交时间、计划首次提交后 spec 改了几次 | `--metrics` |

`${CLAUDE_PLUGIN_ROOT}` 没有被替换成真实路径时，先解析出插件目录再运行；不把脚本复制到用户项目里。

**怎么呈现结果**

- 照实给出结果和各条记录的来源，保留这句说明：「本次为进度记录快照，未重新验收，也未核验交付事实」。
- 同一特性在多个 worktree 里的记录不一致时并列给出，不替用户挑一个当“最新”。
- 这是进度记录，不是验收结论：不去读提交或验收证据来宣称通过。`--metrics` 给出的只是提交时间，批量改动（迁移、回填）也会算进去。
- 脚本没有运行成功就报告失败，不自己编表格。
- 格式错误只报告，不修复、不迁移，也不据此执行计划。

**退出码**：0 表示读取完成（记录里有阻塞或不一致也是 0）；1 表示读取不完整，照样给出读到的记录和 diagnostics；2 表示参数或目标有误，说明原因。

**未知不等于没有**：读取失败的来源，状态一律写“未知”并在总结里单列；统计只包含读取成功的来源。不能因为某个来源没列出任务，就说它没有进行中、待验或阻塞的任务。
